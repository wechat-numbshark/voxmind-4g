# VoxMind 电量不准与关机掉电调查

日期：2026-11-06。对象：EVT v9 实板（`demo-voxmind-not-a-real-device`，固件 1.0.26），1050 mAh 电池。

> 修复已做：固件 `1.0.27-power.1` 和改线步骤见 [32 号文档](32_VoxMind电源修复_固件与改线_20261106.md)。

依据三类材料，每条结论都标了出处：

- 板子网表：`.easyeda/voxmind_v9_mechanical.json`（v9 器件逐脚网络）、`制造文件_v9_20260830/VoxMind_EVT_V1_v9_BOM.xlsx`
- 固件代码：`firmware/components/app_cloud/app_cloud.c`、`drv_power`、`drv_display`、`drv_modem`
- 线上记录：生产库 `vm_audit_log` 里的 `device.boot_diagnostics`（每次开机上报的复位原因）

本次**没有接电流表实测**。设备从 11-03 起离线，下面的电流数字是按器件规格和以前的实测推算的，第 5 节给出了怎么实测。

---

## 1. 结论

| # | 现象 | 根因 | 把握 |
|---|---|---|---|
| A | 关机后过一阵就完全没电 | **4G 模组直接接在电池上，关机断不了它的电**。3.3V 电源也一直开着。所谓“关机”只是 ESP32 深睡眠 + 4G 关射频，整机仍有毫安级耗电 | 高（网表确认） |
| B | 电量不准 | **电池被反复放空 → 电量计跟着断电重置**，重新开机时只能凭当下电压猜电量，经常是插着充电器猜的，偏高 | 高（网表 + 开机记录） |
| C | 电量不准（跳变） | 电量计 QSTRT 脚悬空（数据手册要求接地），CTG 脚也只经电容接地 | 中（网表确认，影响程度要实测） |
| D | 开机时掉电快 | 4G 模组休眠在 1.0.11 起被关掉、ESP32 不开 light sleep，录音时整机约 100 mA 以上 | 高（以前实测） |
| E | 掉电越来越快 | 每次放到电池保护板切断，属于深度过放，会持续损伤电池容量 | 中（推断） |

**电池第三根线（NTC 温度）不是这次的原因。** MAX17048 电量计本身不读温度，第三根线只给充电芯片 BQ24074 做温度保护。现在板上 R4（10kΩ）把 TS 脚固定成“25°C”，充电时没有温度保护，这是安全问题，见第 4 节。

## 2. 关机为什么会把电耗光（A、E）

### 2.1 电路：有两路电，关机都断不了

从 v9 网表逐脚读出（BQ24074、MAX17048 按 TI / ADI 数据手册脚位对照，ISET、ILIM、IN、OUT、BAT 脚全部对得上）：

```
电池 J1.1 ─ VBAT ─┬─ R28 (0Ω) ─ VBAT_MODEM ─ ML307C 4G 模组（U3.42/43）+ 470µF 电解 C32
                  ├─ MAX17048 电量计（U5.2 CELL / U5.3 VDD）
                  └─ BQ24074 BAT（U1.2/3）── OUT ─ VSYS_RAW ─ TPS63802 → +3V3 → ESP32 / SD / 屏 / 触摸 / 灯 / TLV755 → +1V8 → 麦克风
```

- **4G 模组的供电绕开了充电芯片**，经一个 0Ω 电阻直接焊在电池上，中间没有任何开关。以前已经实测确认电源键（PWRKEY）关不掉它（见 memory `modem-pwrkey-cannot-power-off`），复位脚也没接 GPIO。所以电池只要有电，模组就一直在线。
- **TPS63802 的使能脚 EN（U4.1）直接接在 VSYS_RAW 上**，3.3V 电源永远开着。ESP32 模组、SD NAND、屏幕、触摸芯片、WS2812 灯、两颗电平转换芯片在“关机”时都还通着电。
- **BQ24074 的 SYSOFF（U1.15）悬空**。这个脚本来可以把电池和系统断开（运输模式），板上没用上。
- BQ24074 的 /CHG（U1.9）悬空，/PGOOD（U1.7）只接了上拉，没接到 ESP32。固件因此读不到充电状态，只能靠电压跳变去猜（`app_cloud.c` 约 360–400 行）。

### 2.2 固件：“真关机”实际做了什么

`power_off()` → `modem_radio_off()` → `enter_deep_sleep()`（`app_cloud.c` 1289–1540 行）：

1. 屏幕发睡眠指令，背光脚钉低（`display_power_down`）。
2. 4G 退出拨号，发 `AT+CFUN=0` 关射频。**模组本体不关**，而且模组休眠从 1.0.11 起默认关闭（休眠后曾叫不醒），所以它在关机期间处于醒着、串口开着、只是不发射的状态。
3. ESP32 进深睡眠，长按录音键唤醒。

还有三处会在关机期间额外耗电：

- **触摸芯片 CST816D 没有睡**。`display_power_down()` 没有调用现成的 `display_touch_sleep(true)`（头文件注释写深睡约 5 µA），触摸芯片整晚都在扫描。
- **串口 TX（GPIO16）、DTR（GPIO48）在深睡里没有钉住**（只钉了背光和 PWRKEY）。它们经电平转换 U10 接到模组，深睡后变成高阻悬空。CMOS 输入悬空会多耗电，模组的 DTR 也变成不确定状态。
- WS2812 灯不亮时也有静态电流，接在常开的 3.3V 上。

### 2.3 估算：关机电流在毫安级

| 部件 | 关机时状态 | 估计电流 |
|---|---|---|
| ML307C 4G | CFUN=0，没休眠 | 约 几 mA ~ 十几 mA（**最大头，要实测**） |
| 触摸 CST816D | 没进深睡 | 约 0.1 ~ 2 mA（看它的自动省电档） |
| WS2812C 灯 | 静态 | 约 0.3 ~ 1 mA |
| 悬空的电平转换输入 | 不确定 | 0 ~ 1 mA |
| SD NAND、TPS63802、TLV755、MAX17048、ESP32 深睡、麦克风、电容漏电 | 待机 | 合计约 0.3 ~ 0.6 mA |

按合计 5 ~ 20 mA 算，1050 mAh 满电关机能撑约 2 ~ 9 天。用户说的“关机放一段时间就没电”和这个量级吻合。以前 10-03 的实测也对得上：暂停录音 + 关射频时整机 13 ~ 25 mA，其中还包括 ESP32 自己在 80 MHz 下的运行电流。

### 2.4 线上证据：电池确实被反复放空

ESP32 从深睡眠醒来，复位原因是 8（`ESP_RST_DEEPSLEEP`），RTC 里存的上次运行记录还在。电池放空后再插电，复位原因是 1（`ESP_RST_POWERON`），上次运行记录全部丢失（`previous.valid=false`）。

10-11 到 11-03 一共开机上报 14 次，**有 7 次是复位原因 1、上次运行记录丢失**：10-12、10-15、10-18、10-21、10-24、10-30、11-03。从深睡眠正常醒来的只有 4 次。

需要说明：按 EN 复位键（SW5）或 USB 下载复位也会报 1。所以这 7 次里可能有个别不是放空。但每隔两三天就出现一次，和“关机两三天就没电”的节奏一致。

**放空本身也有害**：模组直接挂在电池上，没有任何欠压切断，会一直把电池放到电池保护板动作（通常 2.5 ~ 3.0 V）。每次都是深度过放，锂电池容量会一点点下降。这会让开机时也显得“越来越不耐用”。

## 3. 电量为什么不准（B、C）

### 3.1 电池一放空，电量计就被清零（主因）

MAX17048 的电源也取自 VBAT（U5.3）。电池保护板一切断，电量计就断电，它算到一半的电量随之丢失。下次通电时，它只能用通电那一刻的电压估一个初始电量。而这一刻通常是：

- **刚插上充电器**：电池电压被充电电流抬高，估出来的电量偏高，一个几乎没电的电池可能显示 20% ~ 40%。用一会儿就“掉得飞快”，其实是在回落到真实值。
- **刚开机、4G 正在注册**：电压被大电流拉低，估出来偏低。

固件拿到电量计的数直接显示（`s_battery_pct = soc_pct + 0.5`），没有任何平滑处理，也不知道刚才发生过重置。固件里的 `power_quick_start()` 从来没被调用过，这一点没问题。

### 3.2 电量计的两只脚没按数据手册接（C）

- **QSTRT（U5.6）悬空**。这个脚的上升沿会触发“快速重启”，让电量计按当时的电压重新估电量。数据手册要求不用时接地。旁边 4G 发射时电流可达 2 A，悬空的脚容易被干扰，造成偶发跳变。
- **CTG（U5.1）只经 100nF 的 C21 接地**，直流上仍是悬空。数据手册要求直接接地。

两条网表确认无误，但实际影响有多大要实测。

### 3.3 测的是带载电压，模型也没调过（次要）

- 电量计的采样点和 4G 模组的大电流在同一个 VBAT 节点上，大电流还要流过 J1 插座和电池线。录音、上传时它看到的电压偏低，电量就算得偏低；关机静置后又回升，看上去像“关机还在掉/又涨回来”。
- 固件没写 RCOMP，没有按这颗电池调电量模型，也没有温度补偿（板上没有温度来源）。出厂默认模型在常见锂电上通常误差几个百分点，单这一项不足以解释“很不准”。

---

## 4. 电池第三根线

- J1 的 3 脚是 TS（接 BQ24074 TS 脚），电池的第三根线一般是 10kΩ NTC。现在 3 脚空着，R4 10kΩ 把 TS 固定在“25°C”，充电芯片永远以为温度正常。**高温或低温下照样满电流充电，没有温度保护。** 和耗电、电量不准无关。
- **想接上第三根线，必须先拆掉 R4**。否则 NTC 和 R4 并联约 5kΩ，充电芯片会以为电池过热而停充。另外还要先确认电池的 NTC 是 10kΩ（B 值 3435 或 3950），再接。

## 5. 下一步：先实测，再改

### 5.1 实测（半小时，必做）

1. **关机电流**：万用表 mA 档串在电池正极（J1.1 线上）。正常开机后长按录音键关机，等 2 分钟读稳态值。
2. 在关机状态下逐项排除，看电流降多少：
   - 拔掉屏幕排线：屏 + 触摸那部分。
   - 临时拆 R28（4G 供电 0Ω）：4G 模组那部分。**这一项最关键**，预计占大头。
3. 记下开机录音、暂停时的电流，和 memory `voxmind-power-budget` 里 10-03 的数据对比，看过放之后电池有没有变差。

不方便串表时，可以让固件代劳（见 5.2 第 1 条）：电量计在关机期间一直通电、一直在算，开机时读一下就知道关机期间掉了多少。

### 5.2 固件能做的（不改板）

| 优先级 | 改动 | 作用 |
|---|---|---|
| 1 | 关机前把电量、电压、时间记进 RTC 内存。开机时读电量计，算出“关机 X 小时掉了 Y%”，随开机诊断一起上报 | 不接电流表也能拿到真实关机电流；以后每次关机都自动有数据 |
| 1 | 关机前调用 `display_touch_sleep(true)`，并对 GPIO16（TX）、GPIO48（DTR）用 `gpio_hold_en` 钉成确定电平 | 去掉触摸扫描和悬空输入的耗电，改动小、风险低 |
| 2 | 开机读电量计 STATUS 寄存器（0x1A）的 RI 位，判断它是不是刚被重置过。是的话界面标“电量校准中”；等拔掉充电器、静置一会儿，再用 0x06 MODE 的 Quick-Start 重新估一次 | 解决放空后电量偏高、之后“掉得飞快”的问题 |
| 2 | 显示的电量做单调平滑：放电时不涨，充电时不降，每分钟最多变 1% | 去掉跳变 |
| 3 | 关机时允许模组进休眠（`AT+MLPMCFG="sleepmode",2,0` + DTR 拉高并钉住） | 可能把模组那部分从毫安级降到 1 mA 左右。**风险**：1.0.9 出现过休眠后叫不醒，没有复位线就只能拔电池。必须先用 USB 反复试开关机，验证每次都能叫醒才能上 |
| 3 | 电压低于约 3.3 V 时自动真关机，并提示“电量耗尽” | 少一点深度过放，但模组仍在耗电，治标不治本 |

**能做到什么程度要说清楚**：第 1、2 档能把关机电流压低一些，并让电量显示可信。但只要 4G 模组还直接接在电池上，关机放几天就没电这件事，固件改不彻底。

### 5.3 下一版电路要改的（根治）

1. **4G 模组改从 VSYS（BQ24074 OUT）取电**，并加一颗 ESP32 能控制的负载开关（例如 TPS22918 或 P-MOS）。关机时直接断掉模组，异常时也能断电复位。注意 4G 发射的 2 A 峰值，开关的导通电阻和 470µF 储能要一起算。
2. **SYSOFF 接上运输模式**：做成一个开关或由按键触发的锁存，关机时让 BQ24074 断开电池与系统。关机电流可以到微安级。
3. TPS63802 的 EN 改由可控信号驱动，或靠第 2 条整体断电。
4. MAX17048：**QSTRT 接地，CTG 接地**；CELL 用单独的检测线直连电池焊盘，不和 4G 大电流共用一段走线。
5. /CHG、/PGOOD 接到 GPIO，固件就不用再靠电压去猜充电状态。
6. 电池第三根线（NTC）接到 TS，去掉 R4 固定偏置。
7. MODEM_RESET_N 接到 GPIO（`docs/13` 早已列为 DVT 待办）。

## 6. 数据出处

- 网表关键脚：`R28: VBAT ↔ VBAT_MODEM`；`U4.1 EN = VSYS_RAW`；`U1.15 SYSOFF`、`U1.9 /CHG` 无网络；`U1.7 /PGOOD` 只接 R3；`U5.6 QSTRT`、`U5.5 ALRT` 无网络；`U5.1 CTG ↔ C21 ↔ GND`；`U1.1 TS = J1.3 = R4 → GND`。
- 开机记录查询：`select at, detail from vm_audit_log where action='device.boot_diagnostics' order by at desc`，看 `diagnostics.resetReason` 和 `previous.valid`。
- 服务器不保存电量历史（只有 `vm_devices.last_battery_pct`），所以算不出“关机前 / 开机后”的电量差，这正是 5.2 第 1 条要补的数据。
