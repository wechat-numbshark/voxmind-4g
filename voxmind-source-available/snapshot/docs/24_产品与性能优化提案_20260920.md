这份提案分三部分：**现状盘点**（全是实测数字，不是估算）、**市场调研**（当天查证，标了来源和日期）、**分层改善清单**（功能 + 性能，按"强烈推荐 / 推荐 / 可做 / 先别做"排）。

## 一、现状盘点

### 1.1 设备端（固件 0.9.7 在机，0.9.8 已编译待刷）

**屏幕**：2 英寸 240×320，两屏左右滑动。

| | A 屏（默认） | B 屏（左滑） |
|---|---|---|
| 顶部 | 44px 大时钟、电量、日期/充电状态 | 时钟、日期、录音状态药丸 |
| 主体 | 录音行（状态+走时+电平）、今日统计一行、最多 **2 张**回执卡片 | 今日时刻表，最多 **6 行** |
| 交互 | 卡片左右滑掉；有待确认卡片时占满全屏，可签放/退回 | 待确认那行可点（跳回 A 屏） |

**已确认的三个硬伤**（你提到的"点不进去、标题显示不全"）：

1. **回执点不开**。`slot_event` 只处理左右滑动，`LV_EVENT_CLICKED` 根本没接——点了没有任何反应，只能划掉。
2. **标题被服务端截断**。`app.ts` 的 `short()` 把回执标题截到 **15 个字**加省略号。240px 宽、16px 字，一行能放 13 个字、两行 26 个字，现在只用了半行的信息量。
3. **没有滚动**。A 屏 2 张、B 屏 6 行都是固定槽位，多出来的只能写"还有 N 条"。今天办了 20 件事，设备上永远只看得见 2 件。

**其他设备能力**：三键（暂停/按住说话/确认退回）、触摸、亮度下拉面板、自动熄屏、LED 三档、震动、语音开关机、OTA（含不降级保护和先头机制）、离线本地缓存续传、GB2312 字库（emoji 和生僻字显示为空）。

### 1.2 云端与网页

**7 个工作台页面**：今天、任务中心、自动化、录音、搜索、聊天、我的（6 组设置 + 执行规则）。**7 个管理页面**：总览、用户、设备、成本、执行记录、连接器、审计。

**AI 能力**：转写（qwen3-asr-flash）→ 拆主题 → 会议纪要（4 个模板）/ 思维导图 → 意图抽取 → 语义搜索 → 后台聊天 → 每日小结 → 漏网检查。

**执行能力**：飞书任务/日程/文档/消息、多维表格记账、笔记、Webhook、Home Assistant、定时自动化。每类可单独设"要不要先问我 / 什么时候抽 / 办完推不推到屏上"。

**工程状态**：129 个测试通过；网页打包 386 KB（gzip 118 KB）；单机 Docker（API + Postgres + Caddy），每日备份保留 14 天。

### 1.3 实测性能数字

## 二、市场调研（2026-09-20 当天查证）

### 2.1 海外三家

**Plaud（plaud.ai）**——自称 AI 笔记第一品牌，2.5M+ 专业用户。产品线已经铺成 5 款：Note、NotePin、NotePin S、Note Pro、One（预售）。

值得注意的是**它的首页是按职业分栏的**：高管、中小团队、销售、临床医生、律师、教育者。每一栏一句话价值主张——销售是"保持在场，Plaud 负责记录并起草跟进"，医生是"看着病人而不是屏幕"。它还在推 "Plaud Agent plans and gets it done"（从记录走向代办）和 "memory and context build over time"（跨会话记忆）。

**Bee（bee.computer）**——$49.99，**7 天续航（160 小时）**，双麦降噪，40 种语言。功能清单里有：摘要与要点、**建议待办**、模式与洞察、每日记忆、搜索与对话、**会话模板**、集成与动作、语音备忘。

**Limitless（limitless.ai）**——**已被 Meta 收购**。Pendant 不再向新用户销售，老用户至少再支持一年、订阅免费，Rewind 等非 Pendant 功能将下线。

> 这条信息对我们是双面的：一方面证明这个品类被大厂认可（Meta 下注可穿戴 AI），另一方面说明**独立小厂难以单靠硬件活下来**，差异化必须落在"数据归属 + 能办事"上。

### 2.2 国内两家

**钉钉 DingTalk A1 / A1 Pro**

| | A1（2025-08-25） | A1 Pro（2026-04-30） |
|---|---|---|
| 价格 | 499（青春版）/ 799（旗舰版） | 1299 |
| 形态 | 磁吸卡片，3.8mm，40.8g | 6.4mm，可给手机反向充电 |
| 麦克风 | — | 2 指向 + 3 全向，拾音 10 米 |
| 续航/存储 | 47 小时录音 / 64 GB 本地 | 续航约为 A1 的 4 倍 |
| 软件 | 转写、翻译（21 语种）、AI 听记、分角色纪要 | **200+ AI 纪要模板**（客户拜访、面试问答等） |
| 商业模式 | — | 赠 6 个月、每月 1500 分钟转写，**官方标价值 450 元** |

**科大讯飞**——转写这一层的事实标准：宣称普通话 98%+ 准确率、**区分说话人并按角色分别生成总结**、**自定义专业术语词库**、离线转写、方言、15 米拾音（SR502）。

### 2.3 从调研里提炼的三条结论

1. **"分说话人"是这个品类的入场券，我们没有。** 讯飞、钉钉、Plaud 都有；多人会议场景下没有它，纪要质量会明显差一截。
2. **"纪要模板"是拉开差距的地方。** 钉钉 200+ 个场景模板，我们 4 个。模板成本极低（纯提示词），是性价比最高的一类功能。
3. **转写时长是成本中心，大家都在按分钟卖。** 钉钉把 1500 分钟/月标价 450 元。我们自己一天 8 小时全量转写，成本结构必须心里有数（我们已有按功能分项的花费看板，这一点反而领先）。

### 2.4 VoxMind 现在真正的差异化

别人有而我们没有的，上面说了。**我们有而他们都没有的**，得说清楚，因为这决定了该往哪儿加码：

- **自带 4G，不依赖手机**。Plaud/Bee/A1 都要靠手机 App 中转；我们是独立终端，录完直接进云、直接办事。
- **屏上确认闭环**。他们是"录完给你一份纪要"，我们是"听懂了，插一张单子问你要不要办"，签放后真的去飞书建任务、写多维表格。这是从"记录工具"到"执行代理"的跨越，Plaud 刚喊出 Agent 概念，我们已经跑通了。
- **数据自托管**。录音、转写、向量、动作全在自己服务器上，能导出能删。对律师、医生、咨询这类职业，这是硬需求而不是加分项。
- **按键即授权**。按住说话才抽任务，这个交互在隐私敏感场景下比"全自动"更容易被接受。

### 2.5 不同职业要什么（映射到我们缺什么）

| 职业 | 他们的核心诉求 | 我们的状态 |
|---|---|---|
| 销售/BD | 客户拜访纪要、自动跟进任务、客户维度回看 | 纪要✅ 任务✅ **客户/项目维度组织❌** |
| 医生/诊所 | 门诊记录结构化、患者隐私、术语准确 | 自托管✅ **术语词库❌ 分说话人❌** |
| 律师/顾问 | 逐字可检索、时间戳引用、留痕可审计 | 搜索✅ 时间戳✅ 审计✅ **分说话人❌ 逐字稿导出格式单一** |
| 教师/学生 | 长时间讲座、要点与复习材料 | 主题✅ 导图✅ **长录音的章节体验一般** |
| 开发者/产品 | 会议决策记录、行动项、能接自己的系统 | 决策记录✅ 行动项✅ **开放 API 与 Webhook 未文档化❌** |
| 自由职业/超级个体 | 记账、日程、每日复盘、一个人干多件事 | 记账✅ 日程✅ 小结✅ **移动端体验弱❌** |

## 三、改善清单

### P0 · 强烈推荐（这周做，成本低、疼痛明确）

| # | 事项 | 为什么 | 改动 |
|---|---|---|---|
| 1 | **设备回执点开看详情** | 你亲口提的；现在点了没反应，只能划掉 | 接 `LV_EVENT_CLICKED`，做一个全屏详情页：标题完整换行、时间、类型、原话、状态，返回键退出 |
| 2 | **标题别截到 15 字** | 服务端 `short()` 砍掉了一半信息 | 列表页放宽到 26 字（两行），详情页给全文（≤60 字） |
| 3 | **B 屏时刻表可滚动可点开** | 今天办 20 件事只看得见 6 行 | 改成可滚动列表，每行可点进详情 |
| 4 | **刷 0.9.8** | 暂停时屏幕常亮；轮询浪费三成流量 | 已编译好，插 USB 即可 |
| 5 | **实测电池续航** | 唯一没有实测数据的关键指标，而竞品都在拿续航打广告（Bee 160 小时、A1 47 小时） | 满电开机跑到关机，用心跳里的电量曲线算出每小时耗电 |
| 6 | **流量计** | 你刚问完流量；设备自己知道传了多少 | 设备上报累计字节，网页显示"本月已用/今日"，可设阈值提醒 |

| # | 事项 | 为什么 | 代价 |

## 四、性能优化清单

### 4.1 设备端

| # | 优化 | 现状 → 预期 | 代价 |
|---|---|---|---|
| P1 | **轮询放慢（0.9.8 已做，待刷）** | 2.6 → 0.88 MB/小时 | 屏幕黑着时卡片最多晚 4.5 秒到 |
| P2 | **给设备接口去掉浏览器安全头** | 响应头 604 → 约 200 字节，省约 0.6 MB/小时（约两成） | 几行服务端代码，无副作用 |
| P3 | **音频块 5 秒 → 15 秒** | 每块 1234 字节固定开销摊薄到 1/3，省约 0.56 MB/小时；请求数降到 1/3，网络栈 CPU 跟着降 | 转写晚 10 秒出来；掉电最多丢 15 秒 |
| P4 | **Opus 复杂度 5 → 3** | main 任务 67% 预计降 10–15 个点 | 24 kbps 语音听感几乎无差，但可能轻微影响转写准确率——**要 A/B 实测再定** |
| P5 | **熄屏时降 CPU 频率 / light sleep** | 待续航实测后再定量 | 需要确认不影响录音连续性 |
| P6 | **TLS 会话复用** | 断线重连时省一次完整握手（约 5 KB + 几秒 CPU） | 中等，要确认模组和 mbedTLS 配合 |

做完 P1+P2+P3：安静时段 2.9 → 约 1.8 MB/小时，24 小时/天约 1.3 GB/月。

### 4.2 云端

| # | 优化 | 说明 |
|---|---|---|
| C1 | 转写前的静音过滤再收紧 | 已有 VAD；按实际账单看还有多少是在为静音付费 |
| C2 | 拆主题/漏网检查合并调用 | 现在是两次模型调用，可以合并成一次多任务输出 |
| C3 | 向量检索加 pgvector 索引 | 现在是全表扫描算相似度，录音上万条后会明显变慢 |
| C4 | 音频冷数据转对象存储 | SD 和服务器磁盘都会涨；保留期之外的转冷存或直接删 |
| C5 | 备份异地 | 现在只在本机保留 14 天，机器挂了就全没了 |

### 4.3 网页

| # | 优化 | 说明 |
|---|---|---|
| W1 | 路由级代码分割 | 386 KB 打包，管理页和图表可以按需加载 |
| W2 | 轮询改成条件请求 | 今天页 5 秒一轮、录音页 20 秒一轮，都是整包返回；加 ETag 后大部分是 304 |
| W3 | 长列表虚拟滚动 | 任务中心和录音列表上千条后会卡 |

## 五、建议的执行顺序

**第一周**：P0 全部（设备详情页 + 标题放宽 + 可滚动列表 + 刷 0.9.8 + 续航实测 + 流量计）。这些都是你能立刻感知到的。

**第二周**：性能 P2、P3，然后 P1 里的第 8、9 条（词库、模板）——都是小改动大收益。

**第三、四周**：分说话人（第 7 条）。这是唯一一件"工作量大但必须做"的事，做完我们在多人场景才算站得住。

**之后再看**：移动端 PWA 和按客户组织，取决于你自己用起来哪个更缺。
