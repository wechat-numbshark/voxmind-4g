# VoxMind 开放接口

给想接自己系统的人看的。所有接口都在 `https://EXAMPLE-DEMO-HOST.invalid` 下，返回 JSON，时间一律是 ISO 8601（UTC），显示时按北京时间换算。

## 怎么鉴权

两种方式，二选一：

**1. 管理员密钥（适合脚本、服务器之间调用）**

```bash
curl -H "authorization: Bearer $VOXMIND_ADMIN_KEY" https://EXAMPLE-DEMO-HOST.invalid/v1/sessions
```

密钥在服务器的 `/opt/voxmind/deploy/.env` 里（`ADMIN_API_KEY`）。它等同于管理员身份，**别放进浏览器里跑的代码**，泄露了就能读全部录音。

**2. 会话 Cookie（网页自己用的）**

`POST /v1/auth/login` 拿到 httpOnly Cookie，后续请求带着走。脚本一般不用这种。

**设备用的接口**（路径以 `/v1/device` 开头）走设备密钥 `x-device-key`，和上面两种是分开的，这里不展开。

## 常用接口

### 录音

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/sessions?limit=100` | 录音列表，含时长、主题数、动作数 |
| GET | `/v1/sessions/:id/timeline` | 一次录音的全部块、转写、动作 |
| GET | `/v1/sessions/:id/export.txt?from=&to=` | 纯文字稿（毫秒区间可选） |
| GET | `/v1/sessions/:id/export.wav?from=&to=` | 音频（一次最多 30 分钟） |
| DELETE | `/v1/sessions/:id/audio?from=&to=` | 删掉一段音频，转写保留 |

### 主题与客户

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/sessions/:id/topics` | 这次录音的主题、纪要、导图 |
| PATCH | `/v1/topics/:id` | 改标题、范围，或打客户/项目标签 `{"label":"张总"}` |
| GET | `/v1/labels` | 用过的客户/项目，带条数和最近时间 |
| GET | `/v1/labels/:label/topics` | 某个客户下的全部主题 |

### 动作与提醒

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/action-drafts?status=&tool=&days=&q=&limit=&offset=` | 任务中心那份列表 |
| POST | `/v1/action-drafts` | 从外部塞一个待确认动作进来 |
| POST | `/v1/action-drafts/:id/confirm` \| `/cancel` | 签放或退回 |
| GET | `/v1/reminders` | 到点提醒列表 |
| POST | `/v1/reminders/:id/ack` | 标记已收到 |

### AI

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/search?q=&days=&mode=hybrid` | 按字面和意思搜转写 |
| POST | `/v1/outputs` | 生成纪要或导图 `{"kind":"minutes","targetType":"topic","targetId":"…"}` |
| GET | `/v1/outputs/:id/export.docx` | 纪要导出 Word |
| POST | `/v1/outputs/:id/tasks` | 把纪要里的待办变成飞书任务 |
| GET/POST | `/v1/daily` | 看/生成某天的小结 |
| GET | `/v1/suggestions?status=open` | "说过但没让我办"的建议 |
| POST | `/v1/suggestions/:id/accept` \| `/dismiss` | 采纳或忽略 |
| POST | `/v1/chat` | 和录音对话 `{"messages":[{"role":"user","content":"…"}]}` |

### 自动化

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/v1/automations` | 列出/新建定时规则 |
| PATCH/DELETE | `/v1/automations/:id` | 改或删 |
| POST | `/v1/automations/:id/run` | 立刻跑一次 |

新建的请求体：

```json
{
  "title": "每周一建写周报的任务",
  "schedule": { "kind": "weekly", "time": "09:00", "weekday": 1 },
  "action": { "kind": "tool", "tool": "feishu.task.create", "args": { "summary": "写周报" } }
}
```

`schedule.kind` 可以是 `daily` / `weekly`（带 `weekday`，0=周日）/ `monthly`（带 `day`）/ `once`（带 `date`）。时间都按北京时间。

`action.kind` 可以是 `tool`（配 `tool` 和 `args`）、`daily_summary`、`expense_summary`。

### 设置

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/PUT | `/v1/settings` | 全部设置（档位、保留期、AI 开关、记账、提醒…） |
| GET/PUT | `/v1/tool-policies`、`/v1/tool-policies/:tool` | 每类动作：先问不问、抽不抽、推不推 |
| GET | `/v1/my-costs` | 按功能分的花费 |

## 几个约定

- **出错**：返回对应的 HTTP 状态码加 `{"error":"人话说明"}`。参数不合法是 400，没权限是 401/403，找不到是 404，业务上做不了是 422。
- **别人的数据一律当不存在**：访问不属于你的录音返回 404 而不是 403——403 会暴露"这个 id 是真的"。
- **轮询**：GET 接口都带 `ETag`，把它放进 `If-None-Match` 再请求，没变化会返回 304，省流量。
- **音频接口**标了 `cache-control: private, no-store`，中间的 CDN 不会缓存。
- **写操作都会记审计**，在 `/v1/audit` 里查得到。

## 一个完整例子：把今天的动作同步到自己的系统

```bash
#!/usr/bin/env bash
set -euo pipefail
KEY="$VOXMIND_ADMIN_KEY"
BASE="https://EXAMPLE-DEMO-HOST.invalid"

# 今天已经执行成功的动作
curl -fsS -H "authorization: Bearer $KEY" \
  "$BASE/v1/action-drafts?status=executed&days=1&limit=50" |
  python3 -c '
import json,sys
for d in json.load(sys.stdin)["drafts"]:
    print(d["createdAt"][11:16], d["tool"], d["title"], sep="\t")
'
```

## 还没有的

- **没有 OAuth 和细粒度 token**：现在只有"管理员全权"和"登录会话"两档。要接第三方应用的话得先加 token 管理，这件事还没做。
- **没有 Webhook 推送**：要知道"有新动作了"目前只能轮询。
- **没有速率限制**：自己用没问题，对外开放前要先加。

这三条是开放给别人用之前必须补的，现在这套接口的定位是"给你自己和你信任的脚本用"。
