# VoxMind 低成本物联网开关与农场扩展方案

日期：2026-10-04。状态：架构与 Wi-Fi / ESPHome 起步模板已准备；尚未购买、接线或控制真实负载。本文中的人民币价格是工程预算，不是采购报价。

**最新需求：现在集中放置，但网关到开关必须无线；不限定 Wi-Fi，之后可搬到农场。** 因此当前推荐改为“一只 USB 无线网关 + 四路共用无线控制箱”。非 Wi-Fi 候选以 CH592 私有 2.4GHz 双向链路和 433MHz 简单遥控作比较，详见 [第 13 节：无线降本定案与验证计划](#iot-wireless)。前文 ESPHome 文件保留为备选；它们不是 CH592、433MHz 或 ESP-NOW 固件。

## 1. 先说结论：轻量无线网关，多路共享控制箱

你已有的系统可以直接分成四层：

```text
VoxMind（听懂“打开育苗灯”并生成确认卡）
  ↓ 语义动作 iot.switch.set / iot.light.set / irrigation.zone.run
EVA Core（设备名称映射、幂等、审计；负载级保护仍需补齐）
  ↓ 只允许登记过的动作
Home Assistant（本地设备网关；ESPHome / MQTT / Zigbee / Modbus）
  ↓ USB 无线网关 / 其他适配器
无线控制箱（四路共用一颗无线主控）→ 低压执行器 / 合规接触器 → 真实设备
```

因此：

- **现在家里/工作台**：优先验证一只 USB 无线网关、一只四路控制箱。开关侧不用连接 Wi-Fi；USB 仅连接网关与已有主机，不是把开关改成有线。
- **以后温室**：按区域复制四路箱，复用节点身份、接口与上层程序；改用适合现场的电源、保护和防护箱。
- **以后室外田块**：先测距与遮挡，再增设区域网关；跨田坎不承诺 2.4GHz 全覆盖。远端另评估合规的 sub-GHz 双向链路或 LoRa，RS485 只作愿意布线时的备选。
- **Zigbee 网关是可选项**：只有大量电池传感器时再加一个 USB 协调器，不为第一只开关购买。
- **VoxMind 不是电气网关**：它是可替换的语音/大脑入口；即使云模型或 VoxMind 暂时离线，本地按钮、保护和 Home Assistant 自动化仍可工作。

## 2. 现有 VoxMind / EVA 能否接上

代码审阅结论：软件主链路已经有了，不需要重新发明。

| 已有能力 | 当前代码证据 | 作用 |
|---|---|---|

```text

→ EVA 查绑定 → switch.bench_switch_01_relay → Home Assistant → ESPHome 节点
```

## 3. 三种节点形态（原 ESPHome 备选，接口可借鉴）

### A. 桌面单路节点：先在低压灯或 USB 设备上验证

用途：12/24V 小灯、蜂鸣器、试验电磁阀，或只提供“干接点”的外部设备控制端。

| 部件 | 建议 | 2026-10 小批量估算 |
|---|---|---:|
| 主控 | ESP32-C3 SuperMini / DevKitM-1 | ¥10–18 |
| 执行 | 兼容 3.3V 输入的一路光耦继电模块；或低压 MOSFET 模块 | ¥4–12 |
| 电源 | 先复用合格 USB 5V 适配器 | ¥0–15 |
| 按钮、端子、保险、线材 | 本地开关与保护 | ¥3–8 |
| A1 打印盒 | 阻燃材料优先；开发期普通盒仅用于低压台架 | ¥2–6 材料 |
| 合计 | 不含被控设备 | **约 ¥19–59** |

如果已有 USB 电源、线材和打印件，单路节点通常落在 ¥20–35；若把合格电源、端子、保险和外壳都算进去，未必比 ¥40–50 的成品便宜。DIY 的主要价值是：可维护、可扩展四路、没有厂商云、可接 EVA。

### B. 温室四路 24V 节点：性价比最高的正式方向

用途：四区 24V 电磁阀、卷膜机控制输入、补光接触器线圈、风机接触器线圈。控制箱统一 24VDC，ESP32-C3 用隔离 DC-DC 降压供电。

建议 I/O：4 路输出 + 4 路反馈输入 + 1 个箱门按钮 + RS485 预留。输出只控制低压线圈或干接点；每路都要有保险/自恢复保护、状态灯和清晰端子编号。

小批量模块拼装约 ¥60–130/箱，不含接触器、断路器、电机保护器和防水箱。四路摊销后常比四个消费级智能开关便宜，而且更适合田间维修。

### C. 泵/大风机节点：控制器便宜，功率部分不能省

```text
ESP32-C3 低压输出
  → 中间继电器或 24V 接触器线圈
  → 合格交流接触器 + 热过载/电机保护 + 断路器
  → 水泵/风机

辅助触点 + 电流/流量/压力反馈
  → 节点输入
  → EVA 才能判断“真的启动/真的出水”
```

泵不能只靠一个几元继电器模块，更不能把“Home Assistant 返回 200”写成“水泵已经正常运行”。泵控制箱由合格电工按铭牌、电缆长度、启动方式和当地规范选型；软件节点只接安全低压侧。

## 4. 哪些负载分别怎么控

| 负载 | 推荐执行器 | 是否可自行低压接线 | 完成证据 |
|---|---|---|---|
| 5/12/24V 小灯 | MOSFET 或额定足够的 DC 继电模块 | 可以，先台架限流 | 输出反馈/电流 |
| 24V 电磁阀 | 带续流保护的 MOSFET；必要时隔离 | 可以，但每路保险 | 阀位或流量 |
| 220V 小灯/插座 | 合格成品智能继电器，或 DIN 接触器 | 市电侧不自行裸接 | 辅助触点/功率 |
| 单相/三相水泵 | 接触器 + 电机保护 + 干转/过载保护 | 仅低压控制侧 | 辅助触点 + 电流 + 流量/压力 |
| 卷膜/正反转电机 | 成套正反转接触器，机械/电气互锁、限位 | 仅低压命令与反馈 | 开/关限位，超时停止 |
| 加热器 | 合格 SSR/接触器 + 独立温控/超温切断 | 仅低压命令 | 温度 + 接触器反馈 |

任何会导致淹水、夹伤、火灾、冻害或作物大面积损失的动作，不因“语音听懂了”就自动执行。大模型只提意图，EVA 管策略，现场保护独立生效。

## 5. 单路节点硬件定义

首版模板位于 `iot-switch/esphome/vox-switch-1.yaml`，默认使用 ESP32-C3：

- GPIO4：继电器/MOSFET 控制，模板按常见低电平触发设置；实物模块若为高电平触发必须修改。
- GPIO5：本地按钮，内部上拉，按下接 GND。
- 上电状态：强制关闭（`ALWAYS_OFF`）。
- Home Assistant 通信：ESPHome Native API + 每设备独立加密密钥。
- OTA：复用每设备 API 密钥进行加密并验证上传者；连续启动失败可进安全模式。
- 网络掉线：不反复重启，不改变输出；本地按钮继续工作。

GPIO 是模板，不是所有 C3 小板的通用接线承诺。焊接前必须核对具体开发板原理图、启动脚和板载 LED 占用。首版只接低压测试负载。

### 首个低压样机 BOM

1. ESP32-C3 SuperMini ×1。
2. 明确支持 3.3V 控制、输入与触点标识清楚的一路模块 ×1；若控制 DC 阀优先 MOSFET 模块。
3. 合格 5V USB 电源和线 ×1。
4. 轻触按钮 ×1、2P/3P 端子、每路保险或自恢复保险。
5. A1 打印外壳：控制区和负载端分舱、端子不可被手指碰到、留扎带固定与应力释放。

不要用面包板长期运行，不把 220V 引进 3D 打印的开发盒，不把“继电器标称 10A”当成感性负载可长期 10A 的证明。

## 6. 网络选择：家庭、温室、室外各不同

| 场景 | 首选 | 原因 | 何时升级 |
|---|---|---|---|
| 现在室内 1–10 节点 | Wi-Fi + ESPHome | 零新增网关、实时状态、本地集成 | 无线拥挤或覆盖差 |
| 温室 10–40 节点 | 分区 Wi-Fi；固定控制箱可 RS485 | 检修直观、成本低 | 金属棚遮挡/距离长 |
| 泵房、阀井、长距离固定设施 | 24V + 屏蔽双绞线 RS485/Modbus | 抗干扰、可沿电缆布设 | 雷击区加隔离/浪涌保护 |
| 远端电池传感器 | LoRa/LoRaWAN | 远距离低功耗 | 控制命令必须 ACK、限时和本地保护 |
| 大量门磁/温湿度电池设备 | Zigbee | 低功耗 Mesh | 到那时再买 USB 协调器 |

一个节点只选一条主通信路线。上述为原有备选；最新无线路线见第 13 节。改变射频芯片时，EVA 的 `deviceId` 保持不变，但底层驱动和固件不能直接互换。

## 7. 防雨、防潮与断网设计

- 室外节点采用合适等级的成品防水箱，电缆从下方经防水接头进入，做滴水弯；不要依赖 A1 打印壳本身达到 IP 等级。
- 电子板与箱底留高差，端子朝下；箱内加可更换干燥剂和透气防凝露组件，安装板避免积水。
- 24V 电源集中放在干燥控制柜；田间只走 SELV 低压。长线需按现场雷电风险加浪涌保护、接地和隔离。
- Wi-Fi/云/EVA 中断时：本地按钮可用，自动规则只执行预先批准的有限动作；失联不自动延长灌溉。
- 恢复网络后先上报真实输出与反馈，不用服务器“最后记住的状态”强行覆盖现场。

## 8. Home Assistant 与 EVA 登记流程

### 8.1 刷入节点

复制示例密钥文件，不要提交真实密钥：

```bash
cd /Volumes/neo/projects/voxmind/iot-switch/esphome
cp secrets.example.yaml secrets.yaml
# 在本机填写 Wi-Fi、API / OTA 加密密钥和备用热点密码，字段以示例为准
esphome run vox-switch-1.yaml
```

首刷通常通过 USB；之后可 OTA。Home Assistant 能自动发现 ESPHome，或用节点 IP/主机名手动添加。ESPHome 官方原生 API 是局域网实时连接，并支持加密密钥。

### 8.2 在 Home Assistant 验证

实体名称可能因版本和友好名称生成规则不同而变化，以设备页显示为准。先完成三项：

1. 页面点开/关，低压测试灯正确响应。
2. 物理按钮能切换，Home Assistant 状态同步。
3. 拔掉网络后物理按钮仍可用；重新联网后状态恢复。

### 8.3 在 EVA 绑定稳定业务名

示例请求只展示结构，不含真实密钥：

```json
{
  "siteId": "farm-main",
  "deviceId": "bench-grow-light",
  "name": "工作台育苗灯",
  "spaceId": "workbench",
  "capability": "switch",
  "entityId": "switch.vox_switch_01_relay",
  "protocol": "esphome",
  "stateVerification": "command_only"
}
```

通过 EVA 的 `POST /v1/device-bindings` 登记。然后 VoxMind 只需生成：

```json
{
  "tool": "iot.switch.set",
  "args": { "deviceId": "bench-grow-light", "on": true }
}
```

### 8.4 VoxMind 配置

VoxMind 生产或本地环境配置 `EVA_BASE_URL`、`EVA_API_KEY`、`EVA_SITE_ID`，并将执行模式明确切到 `live`。密钥只放服务端环境变量，不写进网页、固件仓库或本文档。先用模拟负载验证；没有真实反馈的设备标记 `command_only`，不能显示“已确认开启”。

## 9. 安全状态机：便宜不等于简陋

以下是每个节点和 EVA 的目标要求；现有 ESPHome 模板只覆盖其中一部分，不含完整状态机、运行限时或实体反馈：

```text
收到命令 → 校验设备/权限/有效期/互锁 → 接收
→ 执行低压输出 → 等待反馈
→ 有反馈：reported success
→ 无反馈：command_only / timeout / fault
```

硬规则：

1. 上电默认 OFF；哪些设备允许恢复上次状态要逐个审批，水泵、加热、运动设备默认不恢复。
2. 命令有 requestId、截止时间和幂等性；重试不得再次浇水。
3. 卷膜正反转、电机换向必须硬件和软件双互锁，切换方向前有停机间隔。
4. 灌溉有单次最大时间/水量、每日上限、最短间隔、液位与流量条件。
5. 急停、热保护、干转保护、限位不经过 Home Assistant 或大模型。
6. 自动化控制关键设备时保留手动/停/自动三位选择或等效本地旁路。
7. MQTT 控制命令不 retained；ESPHome 节点使用加密 API、加密 OTA 和隔离 IoT 网络。

## 10. 原 ESPHome 样机路线（最新无线路线见 13.7）

### 阶段 0：当天软件准备（本次已完成文件）

- 完成 VoxMind / EVA / HA 控制链路审阅。
- 提供单路和四路 ESPHome 模板、密钥示例与验收表。
- 不声称已有实体设备或现场控制成功。

### 阶段 1：1 个单路低压样机

- 采购约 ¥20–35 核心器件，复用合格 USB 电源。
- 先控制 12V 灯或蜂鸣器，不接 220V。
- 完成 HA → EVA → VoxMind 的开/关闭环与审计。
- 连续 72 小时运行，做 30 次断电、断网、重复命令与本地按钮测试。

验收通过条件：上电不误开；断网按钮可用；重复请求只动作一次；实体状态一致；VoxMind 错听时能在确认卡拦截。

### 阶段 2：温室四路 24V 控制箱

- 两路 24V 阀 + 一路灯/风机接触器线圈 + 一路备用。
- 加流量、液位、箱内温湿度、门磁和 4 路反馈输入。
- 先影子运行，再允许小范围自动控制；防水、防凝露、掉电恢复和人工旁路实测。

### 阶段 3：农场总线与泵房

- 现场测绘电缆、距离、负载、接地、雷电和网络覆盖。
- 继续使用分区无线控制箱；对长距离与金属柜遮挡做现场试验，必要时加区域网关。24V + 隔离 RS485 仅为愿意布线时的备选，不取代本次无线要求。
- 泵柜由合格电工完成，EVA 加资源锁、灌溉配方、流量闭环、暴雨联锁和维护工单。
- 远端传感器再评估 LoRaWAN；大量电池设备再加 Zigbee，不提前堆网关。

## 11. 采购决策

原先“先买 ESP32-C3”的建议调整为：先核对 2 块同型号、可用官方 RF_PHY 示例的 CH592 开发模块，以及下载工具/USB 接口；一块做网关，一块做节点，先用 LED 验证双向通信。通过后再接一块四路低压执行板。若目标只是临时开关普通灯，可独立走第 13 节的 433MHz 路线，但必须先查清控制模式。现在不批量采购，也不先画市电 PCB。

定制板前需完成四路样机、接口冻结、实际距离测试和环境/保护验证，并根据真实报价计算摊销。20–30 个节点不一定够回本；按“开发打样费 ÷ 每箱实际节省额”计算，而不是把四路算成四个独立无线节点。

## 12. 已知边界与资料

- ESPHome safe mode 可在连续启动失败时保留网络与 OTA 恢复能力：<https://esphome.io/components/safe_mode/>

本方案没有完成市电设计审查、EMC/IP 认证、现场布线、负载选型或真实闭环测试。它提供的是起步架构和已做配置校验的 ESPHome 模板，未完成编译或上板测试；第一只低压样机通过后，才进入温室控制箱设计。

## 13. 无线降本：不限定 Wi-Fi，按“网关 + 四路箱”设计

### 13.1 最终判断与三个容易混淆的概念

**可以用便宜的非 Wi-Fi 协议。当前最值得验证的是 CH592 私有 2.4GHz 双向节点；最低门槛备选是 433MHz 接收式遥控，但只用于低风险、无需可靠回报的设备。** 这是候选架构选择，不是已经证明 CH592 的完整成品最便宜。

- **无线不等于 Wi-Fi**：433MHz ASK/OOK、私有 2.4GHz、BLE、Zigbee 都可以无线传输。频率不是协议；同为 433MHz 或 2.4GHz 的两块板不一定互通。
- **没有路由器不等于没有网关**：电脑上已有 EVA / HA，网关可以只是插在电脑上的一个 USB 无线棒，不必是一台昂贵小电脑。若电脑关机，远程控制会停止，节点的本地安全功能仍应有效。
- **一个无线节点不等于一个开关**：四个设备在一起，只需一颗无线主控驱动四路独立输出。省掉的是重复的主控、电源和外壳，不是省掉每路必要的执行器与保护。

所有节点仍需供电；“无线开关”只是控制信号无线。普通常吸合继电器不适合长期靠小电池供电。若必须电池化，要另选磁保持继电器/脉冲阀并重新设计电源、实际状态检测和失电行为。

### 13.2 协议与硬件路线比较

| 路线 | 节点端构成 | 能否回报 | 开发代价与限制 | 本项目选择 |
|---|---|---|---|---|
| 433MHz ASK/OOK + EV1527 类遥控 | 接收/解码 + 输出板，可不另放通用 MCU | 廉价接收板通常不能 | 开源 RF 网关容易接入；固定码可能被重放，型号间模式差异大 | 仅普通灯、提示器等低风险临时用途 |
| CH592 私有 2.4GHz | 一颗带无线的 MCU + 驱动/输出 | 可设计双向命令、状态、故障 | 官方有 RF_PHY 示例；需自己写网关桥接、命令、安全与更新逻辑 | 长期自制四路箱的首选验证候选 |
| nRF24L01+ / Si24R1 + MCU | 无线收发器 + 外部 MCU | 可以；另做应用层确认 | MySensors 可减少协议开发；两颗芯片、接线和供电也有成本 | 优先开源复用时的备选，不能直接认定更便宜 |
| ESP-NOW / ESP32-C3 | ESP32-C3 + 驱动/输出 | 可以；需应用层确认 | 不需要连路由器，但仍用 Wi-Fi 无线硬件；同芯片不会因换协议变便宜 | 复用已有 C3 的备选，不叫“非 Wi-Fi 芯片方案” |
| Zigbee | Zigbee 芯片/模块 + 协调器 | 可以 | 标准生态更省维护；模块、协议适配与调试也要计价 | 后期电池传感器或买成品时再评估 |
| sub-GHz FSK / LoRa | 相应收发器/集成 MCU + 执行器 | 可设计双向 | 需链路预算、当地频谱合规、重试与容量规划 | 远端田块另设分区，不用于视频或唯一安全链路 |

开源证据：[MySensors 继电器示例](https://www.mysensors.org/build/relay)及[Home Assistant 官方集成](https://www.home-assistant.io/integrations/mysensors/)可复用；[WCH RF_PHY 示例](https://github.com/openwch/ch592/blob/main/EVT/EXAM/BLE/RF_PHY/APP/RF_PHY.c)提供收发/回调基础，但不是完整智能开关工程。该 WCH 示例带有面向 WCH MCU 使用的许可限制，不能把“源码可看”当作任意平台通用许可。

[Espressif 的 ESP-NOW 文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c3/api-reference/network/esp_now.html)明确要求通信信道匹配，并说明发送回调成功不保证应用层收到数据。因此换成 ESP-NOW 也仍需应用层确认、去重和安全设计；它不是把现有 Wi-Fi YAML 改个名称就完成。

### 13.3 433MHz 为什么便宜，以及不能省掉的代价

最小路线：已有主机 → MQTT → OpenMQTTGateway + 433 发射模块 → 433 接收开关。网关可使用支持的串口方案，或允许网关一侧走局域网；开关端仍不使用 Wi-Fi。具体网关固件、板型和引脚需要锁定，不能默认所有 C3 预编译固件都支持。

[OpenMQTTGateway 官方 RF 文档](https://github.com/1technophile/OpenMQTTGateway/blob/development/docs/use/rf.md)区分 RCSwitch / Pilight 收发与 rtl_433 接收。**rtl_433 不是发射控制器；给网关加接收模块，也不会让只有接收功能的开关突然能够回报状态。**

采购一定问清：

1. 四路是否各自都有明确 ON、OFF 指令？能否四路同时开启？
2. 上电默认什么状态？同一命令连续收到三次会怎样？
3. 有没有物理反馈，而不只是网页记住“上次发送了开”？
4. 电源电压、逻辑接口、负载类型和保护是否符合实际用途？

常见的三种模式不能混为一谈：点动是按住/短时动作；自锁 Toggle 是每按一次翻转；互锁 Latching 可能是开一路时关掉其他路。比如 [QIACHIP KR1204-4 官方页](https://qiachip.com/collections/qiachip-remote-control-switches/products/copy-of-433mhz-universal-wireless-remote-control-switch-dc12v-4ch-relay-receiver-module-and-rf-transmitter-433-mhz-remote-controls-kr1204)列出这三类，**不足以证明它能把四路分别可靠地设置为 ON/OFF**。2026-10-04 页面起价为 US$5.99，具体组合、税费、运费另算；这不是国内到手报价。

对 Toggle 开关，重试可能把灯又关掉，所以没有反馈时不可盲目重发，也不应在 VoxMind 中假装它支持可靠的 `set(on=true)`。宁可只暴露“发送遥控按键”，明确状态未知。固定码接收板不作为门锁、无人灌溉、水泵、加热器或卷膜电机的主要控制器。

### 13.4 我给你设计的主候选：VoxLink-24 四路箱

VoxLink-24 是本方案暂定名称，不是现有开源产品。采用 CH592 私有射频，不要求节点连 Wi-Fi，也不要求每个开关有 IP 地址。

```text
VoxMind：语音与确认
    ↓
EVA：设备名、权限、任务与审计
    ↓
Home Assistant / MQTT 设备适配
    ↓
本机网关桥接进程 ── USB ── CH592 无线网关
                              ))) 私有 2.4GHz 双向无线
                  ┌───────────┼───────────┐
                  ↓           ↓           ↓
               桌面四路箱   温室 A 四路箱  温室 B 四路箱
               灯 / 风扇    阀 / 补光     阀 / 通风
                  ↓           ↓           ↓
             本地按钮、限时、反馈、独立保护
```

第一版使用星型网络，不先写 Mesh。网关靠近已有常开主机；如果主机到温室太远，把区域网关放到覆盖点，由有线网络或已有网络回传。各区分离网络标识与密钥，同一节点同一时刻只有一个有效控制者；跨网关接管要有明确租约和状态重新同步，不允许两个网关争抢开关。

**四路节点硬件边界：**

- 同型号 CH592 开发模块，核对天线、晶振、电源、GPIO 和官方示例支持；不要只看芯片价买裸片。
- 稳压电源、4 路执行驱动、每路保护和端子。电磁线圈需正确的续流/浪涌抑制，不能用 MCU 引脚直接驱动。
- 输出子板可选：12/24V DC MOSFET、低压干接点继电器、接触器控制接口。不同电压/电流不能用“一块万能板”不经选型地混接。
- 4 路反馈输入按需要加隔离/滤波；按钮与反馈不是同一回事。预留手动/停/自动控制，掉电不误动作。
- 程序下载/维护接口必须保留。第一版可先有线升级；无线升级后续需校验、认证、掉电恢复，不冒称已支持 OTA。

CH592 芯片能力以[沁恒资料](https://www.wch.cn/downloads/CH592DS1_PDF.html)为准。本次打开 [LCSC 的 CH592F 页面](https://www.lcsc.com/product-image/C39831287.html)列示 1 颗 US$0.9139、100 颗单价 US$0.5786；搜索缓存中的价格略有差异，以实际订单为准。**这是裸 IC，不含天线、PCB、装配、下载工具或输出电路，不能拿它直接与完整 ESP32 开发板比价。** 下单前需重新查价、库存与型号。

### 13.5 双向通信必须达到什么程度

建议网关到节点的紧凑消息包含：协议版本、网络/节点编号、当前会话、命令编号、通道、目标状态、有效期/租约、最大运行时长和认证标签。主机 JSON 的 `requestId` 映射为节点可处理的短命令编号，不原样塞进无线包。

| 消息/状态 | 真实含义 | 可以对用户怎么说 |
|---|---|---|
| 网关收到请求 | 软件接收了命令 | 已提交 |
| 射频 ACK | 收到无线数据 | 节点已收到，尚不代表执行 |
| 节点应用 ACK + 输出回读 | 执行程序设置了 GPIO | 控制输出已设置 |
| 辅助触点/电流 | 接触器动作或负载取电 | 对应电气反馈已确认 |
| 流量/压力/阀位 | 设备产生预期物理效果 | 已出水/阀位已到达 |

要求：只发明确 SET_ON / SET_OFF，不用 Toggle；重复命令只回报原结果、不延长运行期限；乱序或旧会话命令拒绝。MQTT 命令不 retained；重连先查询状态，旧“开”命令不补发。状态消息可以保留，但必须含时间戳、会话和可用性，过期不能继续显示在线。

配对需要本地按键开启短时窗口，使用每节点独立密钥；使用经过审查的认证加密实现与防重放计数，不自行发明密码算法。重启后计数/会话更新须防止旧包再次生效，Flash 磨损也要考虑。CRC、射频地址和 ACK 都不等于身份认证。

最大运行时间必须由节点本地计时，不依赖电脑、云模型或下一条“关闭”命令到达。掉线后的安全状态按设备分别定义：灌溉通常应限时停止，温室通风可能应由独立温控继续工作，不能所有负载一律立即断电。泵干转、过载、超温、限位等保护另有现场硬件。无线急停不替代硬接线安全回路。

### 13.6 真正算总账：每箱成本，而非只报芯片价

以下为设计预算区间，**不是已拿到的 BOM 报价，也不是已验证最低价**。统一比较“低压控制电子部分”：无线主控、驱动、四路小型执行器、基础端子；不含被控设备电源、反馈传感器、市电功率器件、防水箱、安装、税运、开发与认证。

| 方案 | 一次性网关预算 | 每只四路节点预算 | 说明 |
|---|---:|---:|---|
| 433MHz 模块拼装 | ¥20–45 | ¥25–55 | 未锁定具备四路独立 ON/OFF 的低价 SKU；不保证满足自动控制要求 |
| CH592 开发模块验证版 | ¥20–40 | ¥35–65 | 需要固件与主机桥接开发，首次下载工具另计 |
| CH592 约百台定制目标 | ¥15–30 | ¥22–40 | 只是设计目标，需完整 BOM、PCB/装配/测试/良率报价确认 |
| 已有 C3 改用 ESP-NOW | ¥15–30 | ¥35–65 | 通信方式改变，芯片与执行器成本不会自动减少 |

基础桌面低压电源与简单外壳，另暂留 ¥15–30/箱；如果需要高功率负载电源或户外防护，这个区间不适用。以 CH592 模块方案举例：网关 + 首只四路箱约 **¥70–135**，以后每增加一个类似四路箱约 **¥50–95**。这是低压台架预算，不等于四只已认证 220V 智能插座的替代成品价。

成本公式：总投入 = 网关 + 节点数 × 每节点硬件 + 电源/外壳/安装 + 一次性研发打样 + 长期维护。假设定制比模块每箱省 ¥6，而打样/返工固定费 ¥600，仅此项就要 100 箱才摊平，尚未计算开发时间；这只是解释计算方法，不是本项目报价。**只有 1–3 箱时，便宜芯片未必带来便宜项目。**

四路比单路更合适，是因为你目前集中放置；若以后四个设备分散在不同地块，原来的一箱四路不能凭软件变成四个无线终端，仍需新增节点。八路可后续扩展，但共用电源/无线失效会影响全部八路，关键设备应分箱。

### 13.7 现在到农场的落地顺序

1. **先验证一对无线模块。** 一块网关、一块节点，用 LED 做 ON/OFF、ACK、超时、重复命令、重启和认证测试。采购前确认开发模块资料和下载方法，不先下裸芯片批量单。
2. **再接四路低压输出。** 先小灯/蜂鸣器，后小风扇/阀。分别记录发令、节点应答、输出、电流等证据；本地按钮不经过大模型。
3. **打通软件。** 增加串口网关桥接、MQTT 实体/可用性、EVA 负载风险与命令期限、物理反馈等待。VoxMind 沿用 `iot.switch.set`，但只对白名单设备开放。
4. **验证稳定性。** 72 小时台架运行、至少 1000 次低风险测试指令、重复/乱序/丢包注入、30 次断电重启；记录失败与最大延迟，不能只统计平均值。关网关、关主机时本地限时与手动控制仍应有效。此门槛是初验，不是安全认证。
5. **迁移现场。** 温室金属骨架、含水作物、雨湿环境、金属箱会改变射频效果；按实际天线位置与农场最长链路复测。先一栋温室，不承诺单网关覆盖整座山地农场。
6. **再扩展远田与户外柜。** 复用上层 `deviceId`、端子定义、应用层消息与日志；更换射频时需要适配驱动/网关，防水箱与电源也可能更换。印有 IP 等级的空箱经过钻孔、接线后仍需验收整机防护，A1 打印件用于低压台架、支架和遮雨辅助件，不充当市电安全外壳。

先按单网关 8–16 只四路箱做压力测试，这是测试规模，不是芯片容量保证。心跳错峰、低优先级遥测限流、重试退避，按现场最坏延迟与丢包决定容量；不要拿理论地址数量当实际可控节点数。所选频段、功率、带宽和天线需符合部署地适用要求，私有协议并不豁免射频合规。
