# VoxMind 1.0.24：屏幕与执行链路加固

日期：2026-10-10。主仓 `/Volumes/neo/projects/voxmind`，分支 `v7-connectors-relayout`。

本次从用户实拍的回执覆盖/消失继续检查固件、网络协议、音频缓存、动作执行和迁移能力。保留现有交互、主题、设备映射与密钥配置，没有自动控制空调或重放旧物理动作。

## 已修复

| 范围 | 原因/风险 | 处理 |
|---|---|---|
| 暂停页 | 暂停卡 74px + 回执 54px + 间距超出 124px 可用区；依赖 LVGL 延迟更新后的高度造成闪现 | 暂停信息放回状态行；纯布局规划同时预算卡片、间距、描边；通常保留两张回执 |
| 长文字 | 固定临时缓冲切断中文，提醒文字挤掉底部入口 | UTF-8 边界截断；标题/正文定高省略；保留确认入口 |
| 滑动回执 | 刷新时槽位重排，动画结束按旧索引处理 | 绑定按下时 ID；刷新取消手势；后台拒绝入队不移除；16 项内存待同步表重试删除 |
| 回执协议 | 旧固件 3072 字节接收区可能装不下 4 回执+10 时间线；截断 JSON 导致空白 | 新固件堆上 16KiB 有界接收，超限明确失败；云端按协议版本限制序列化 UTF-8 字节数；错误响应保留原显示 |
| 原话详情 | 云端已有 evidence，设备解析遗漏 | 回执和时间线均接收原话 |
| 操作反馈 | HTTP 200 不代表已执行；重复发送确认有歧义 | 按草稿状态反馈；确认不盲目重试；结果未知要求同步/核实 |
| 动作并发 | 定时执行和多次确认可能同时领取同一动作 | PostgreSQL 事务锁定草稿并原子领取执行权；仅 confirmed 可执行；执行前重新读取存储版本 |
| 物理安全 | 超时后可能已发出红外指令，再试会重复控制 | 物理/破坏性失败记 unknown；不自动重放；旧卡片拒绝重试；超过 10 分钟的中断执行恢复为未知 |
| 卡片过期 | 仅靠定时清扫，过期窗口仍可确认 | 确认时与执行领取事务内校验截止时间；状态转移采用比较更新 |
| 语义一致性 | 网页聊天缺少语音端的设备能力提示 | 两入口共享设备白名单提示；控制、提醒、否定、引用和未登记命令在语义层区分；标签由结构化工具名决定 |
| 录音计时 | 暂停后墙钟补时继续增长；分段计数不连续 | 累计有效编码采样，云端快照补本地计数差 |
| I2S | 驱动接口要求毫秒，旧代码传 ticks，100Hz 下 1000ms 变成 100ms | 直接传毫秒 |
| 存储 | 挂载失败触发自动格式化，可能丢待传录音 | 正式模式禁止自动格式化；只保留 bring-up 模式显式行为 |
| Opus 切档 | 先销毁旧编码器，新配置失败无法兑现“保留旧编码器” | 新编码器打开成功再关闭旧实例，失败恢复旧句柄/帧大小 |
| 新服务器迁移 | 全新库先 ALTER vm_usage 再 CREATE，初始化失败 | 先建表后更新约束，支持 embedding 计费类型 |

## 尚未完成的长期优化

1. **物理状态闭环**：红外是 command_only；接口成功只是命令送达，不等于空调真的开机。需要独立功率/状态反馈才能标成“已验证开机”。
2. **设备能力注册**：目前共享的是已配置提示词，仍需将 EVA 设备能力注册表自动同步成可验证 schema；模型提示不等于绝对不会误判。下一阶段可添加真实模型多轮评测集和拒绝率/误触发率指标。
3. **离线删除持久化**：本次待同步删除存在 RAM；确认送达前重启仍可能重新显示旧回执。后续使用有容量上限的 NVS/日志，控制写放大。
4. **录音统计最终一致性**：当前 UI 补时是有效编码采样估算；最终云端已入库音频时长仍为准，失败片段/积压上传可能使下一次云端快照调整数字。
5. **性能实测**：暂停时停止电平刷新、响应从任务栈改有界堆内存，但尚未做新版全天续航、4G 流量、峰值内存/CPU、触摸帧率及长时压力测试，不虚报提速或续航百分比。
6. **真机目视验收**：OTA 版本与成功心跳可远程确认；最终屏幕观感和手感仍需设备实拍/串口截图复核。

## 可重复检查

```sh
cd cloud
npm run typecheck && npm test && npm run build
# TEST_DATABASE_URL 仅允许 /voxmind_release_*_test 数据库；执行器不触发物理设备
node test/release-postgres-check.mjs
cd ../firmware
export IDF_TOOLS_PATH=/Users/neo/esp/idf-tools
. /Users/neo/esp/esp-idf/export.sh
bash tools/build-release.sh
cmake -S components/ui/tests/host -B build-cloud-current/ui-host
cmake --build build-cloud-current/ui-host -j8
(cd build-cloud-current/ui-host && ./ui-check)
```

构建脚本只检查/编译，不自动上传或触发 OTA。云端与固件分开提交，发布证据再单独提交，便于定位/回退。
