# VoxMind 1.0.25：指令响应与故障诊断

日期：2026-10-11（北京时间）。仓库 `/Volumes/neo/projects/voxmind`，分支 `v7-connectors-relayout`。

## 本次边界

用户报告 1.0.24 在“空调关机”处理中出现黑屏、全部按键无响应，同时联网语音指令偏慢。正常背光超时不是故障，本版保留 `screenOffSec`、`wakeOnCard`、`wakeOnDone` 和现有交互，不通过保持亮屏来加速。

原始事件尚未捕获崩溃现场，不能宣称已找到或彻底修复“莫名关机”的唯一根因。该次关闭空调被正确识别为 `iot.ir.send`；未发现对应设备关机审计，定时关机关闭。USB 接入观察到的复位不能作为此前故障证据。

## 依据与修复

| 环节 | 查到的问题 | 本版处理 |
|---|---|---|
| 终端指令通知 | 熄屏后的通信等待为 15 秒；PTT 标记队列不会唤醒它 | 按下/松开、卡片操作通知通信任务；有指令待处理时按 1.5 秒轮询，空闲熄屏仍为 15 秒 |
| 音频上传 | 原优先上传排除同一会话，且只扫描前 32 块 | 按指令时间区间选择真实索引中的音频块，顺序上传，包含同一会话及第 32 块以后的命令 |
| 落盘调度 | 上传任务固定睡 2 秒，新音频不通知 | 音频安全落盘后通知上传；先提交真实时间索引再公开最终文件；说话和尾音期间不启动新的背景上传 |
| 云端调度 | 一轮 Promise.all 等所有阶段结束后才能开始下一轮 | 人声检测、ASR、意图、向量各有独立循环及单飞锁；慢向量不阻塞下一轮语音 |
| 积压优先级 | 优先了会话，却仍从同一会话最老块开始 | 选中真正覆盖指令的块；处理结束后旧背景音频仍可补处理 |
| 乱序/半句话 | 指令尾部先到可能遗漏前面的否定；静音可能截断指令 | 已知按住区间需覆盖起点、结尾和连续块；包含中间静音一起识别；ASR 领取使用数据库事务锁，全成或全不成 |
| 关机语义 | 唤醒词后短窗口内出现关机即触发，可能误认设备对象或否定 | 整句保守白名单；只允许直接本机开关机；拒绝空调、不要、转述、引用、定时、提问和混合请求 |
| 故障定位 | 串口日志不在故障后留存，云端不知界面是否活着 | RTC 双槽校验留痕、复位原因、主动关机/重启原因、UI/通信/上传心跳年龄；随设备心跳上传受限字段并写审计 |
| 耗时定位 | 很难分清上传、识别和模型等待 | 固件 HTTP 通道、字节、尝试次数、耗时；云端各阶段计数/耗时及 ASR 耗时日志 |

历史样本：打开空调的工具调用约 1.14 秒；关闭空调的标记收到到最后音频到达约 6 分 22 秒，音频到齐至卡片约 3.2 秒。同一时段一个上传请求持续约 89 秒（包含传输和服务端处理，不等于模型耗时）。本版消除已证实的调度等待，但不能承诺消除 4G 链路抖动。

## 诊断字段

- `healthAgeMs` 顺序：UI/LVGL、动作通信、上传；`-1` 表示还未观察到，而不是卡死。
- `plannedStop`：0 无、1 录音键、2 远程、3 语音、4 定时、5 网络恢复、6 UART 回退、7 OTA 回滚、8 OTA 完成、9 唤醒、10 配置更新。
- `event`：0 启动、1 指令松手、2 HTTP 开始、3 HTTP 结束、4 录音写入错误、5 预留 UI 迟滞、6 OTA 暂停绘制。
- RTC 记录不写 Flash/SD，不能保证完全断电后保留。仅校验有效且不是冷启动时使用上一轮数据。Espressif 的 [RTC 内存说明](https://docs.espressif.com/projects/esp-idf/en/v5.5.1/esp32s3/api-guides/memory-types.html#rtc-slow-memory) 是所用存储机制的参考。
- 云端记录启动、心跳状态类别变化及至多每 5 分钟一次常态快照；不记录原话/密钥。服务重启后可能多一条启动快照，不应直接按审计条数计算重启次数，应按 `bootId` 去重。
- 新指标只作为证据，不触发新的自动重启策略。原有网络恢复与 OTA 回滚机制保留。

## 尚需实机验证的边界

1. “全部按键无响应”的原始根因未确认。观察本版是否复发，再按新诊断判断 UI 停滞、软件重启或供电问题。
2. 没有主动执行真实空调/飞书动作；提速需用户正常说话后的真实上传→识别→卡片→确认→执行时间，不能以模拟测试声称端到端秒数。
3. 正在进行中的网络请求不强行取消，避免未知结果和连接并发问题；蜂窝信号、上传重传仍影响最坏耗时。
4. 指令完整性检测允许起点最多 200ms 的麦克风恢复偏差、尾部 80ms 的编码舍入。超过 120 秒或异常缺块的按住区间保守等待，不把截断内容当完整物理控制。后续可单独做超长口述模式。
5. RTC 不能替代掉电保持存储或硬件电源测量；本版不声称已验证全天稳定性/续航。
6. 构建时锁文件依赖审计报告 4 个生产依赖告警（1 中、3 高）。本次没有扩大范围升级依赖，应另行按实际影响分析与回归处理。
