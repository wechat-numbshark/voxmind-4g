## 1.5 下单前要知道的 2 条 DRC

都是既定项，不影响下单：

1. **`MICROSD_N5` 开路** —— U9 脚7（SD DAT1）的上拉。本设计走 SD-SPI 模式，
   SPI 模式下 DAT1 按规范就是闲置的，允许悬空。经硬可达性判定，该脚的逃逸通道
   被 `SD_MISO`（真信号）占死，唯一替代是撕掉内层的 LCD_CS —— 不划算。
   DAT2 那一路（`MICROSD_N6`）的上拉已布通。

2. **同一条的另一半** —— DRC 把该网的一个过孔和 U9_7 分别报了一次。

> 之前那条查不掉的 `Netlist Error` 已在 8/29 清除（重跑 `import-changes` 后消失）。

## 2.3 ⚠ 电池必须买两线的

板上 `J1` 是 3 脚：`1=VBAT  2=GND  3=TS(温度检测)`。

板上 **R4 是 10kΩ 从 TS 接到 GND** —— 这是 TI 手册里「禁用外部温度检测」的标准配置。

| 接法 | TS 阻值 | 结果 |
|---|---|---|
| **两线电池，J1 第 3 脚悬空** | 10kΩ | ✅ 正常充电 |
| 三线电池，NTC 接到第 3 脚 | 10k ∥ 10k = 5kΩ | ⚠ 被判过温，**停止充电** |

**买两线的，或者买三线的但把第 3 根线剪掉不接。**

## 2.5 飞线怎么焊

**只有 SIM_N4 那根是必须的：**

```
起点：R16 内侧焊盘   坐标 (57.10, 19.94) mm   顶层
终点：过孔          坐标 (68.53, 22.00) mm
长度：约 11.6 mm
```

坐标原点是**板子左下角**。对照 `VoxMind_EVT_V1_v6_PCB.pdf` 找位置。

**步骤：**

1. 用放大镜找到 R16（它旁边是 R17/R18/R19，一排四个电阻），确认是**内侧**那个焊盘
2. 助焊笔在两个点各涂一点
3. 烙铁尖蘸一点锡，在起点焊盘上**先点一个小锡珠**（预上锡）
4. 剪一段约 15mm 的 0.1mm 自剥漆包线，一端用烙铁加热上锡
5. 把线头按在起点锡珠上，烙铁一碰即走（**1~2 秒**，别久烤）
6. 另一端同样焊到目标过孔
7. **拉一拉确认牢固**，然后点 UV 胶固定（或一小滴 502）
8. 万用表通断档确认两点导通、且没有和旁边短路

另外两根（TP_RST 6.8mm、EN 13.7mm）可以先不焊 —— EN 完全不影响使用，
TP_RST 只影响触摸屏复位（屏幕本身还能用）。等你手熟了再补。

## 2.6 电池座 J1（如果 SMT 没贴）

3 个脚，2.0mm 间距的插件座，是全板最好焊的件：

1. 把座子插进板子的 3 个孔，注意**开口朝外**（对着板边）
2. 翻到背面，烙铁同时碰住焊盘和引脚
3. 送锡丝，看到锡自然流满孔就撤
4. 三个脚都焊完，检查有没有连锡

# 第三部分：驱动与开发指导

## 3.1 板子回来之后的顺序（不要跳步）

完整清单：`docs/13_首板Bringup清单.md`。核心顺序：

```
第0步 通电前检查（万用表，5分钟）
   ↓
第1步 焊 SIM_N4 飞线
   ↓
第2步 电源链验证（只插USB-C，不装电池）
   ↓
第3步 烧录通路打通
   ↓
第4步 跑自检固件，逐项对照
   ↓
第5步 接屏幕
```

### 第 0 步：通电前（关键，跳过可能冒烟）

万用表**二极管档/通断档**，量以下各点对 GND 的阻值，**都应该 > 几百 Ω**：

- USB-C 的 VBUS
- VBAT（J1 第 1 脚）
- 3V3（找任意 3V3 测试点或 U4 输出脚）
- 1V8（U6 输出脚）

**任何一路接近 0Ω 就是短路，绝对不要上电。**

再目视检查四个方向：`U9`(NAND)、`Q2`(三极管)、`U7`/`U8`（两颗长得一样，别贴反）。

### 第 1 步：电源链

**只插 USB-C，不装电池。** 按顺序量，上一级不对就别往下查：

```
USB-C VBUS  →  5V       （量 F1 后面）
VSYS_RAW    →  约 4.4V  （U1 BQ24074 输出）
+3V3        →  3.3V     （U4 TPS63802 输出）
+1V8        →  1.8V     （U6 输出，常开无软件开关）
```

### 第 2 步：烧录

两条路：

- **USB-C 直连** —— GPIO19/20 是 ESP32-S3 原生 USB，`idf.py flash` 应该直接认到
- **J8 排针** —— `1=3V3  2=GND  3=TXD0  4=RXD0  5=EN  6=IO0`

烧不进去按这个顺序查：

1. 串口有输出吗？没有 → 量 EN 脚应为高
2. 一直复位重启 → **量 GPIO45**。它是 VDD_SPI 选压脚，被拉高会让 flash 供电变 1.8V 直接启动失败
3. 报 PSRAM 错 → `sdkconfig` 里 `CONFIG_SPIRAM_MODE_OCT` 必须为 `y`（N16R8 是八线 PSRAM）

## 3.3 四个会烧掉一整天的硬件坑

**这四条务必先看，否则会白查很久：**

### ① `MODEM_RXD` / `MODEM_TXD` 的网名是 **MCU 视角**

> **⚠ 2026-08-29 更正：这条以前写反了。** 实测（活原理图读模组符号脚名）：
> U3 脚17 = 模组 RXD、脚18 = 模组 TXD，两家模组（Air780E / ML307C-GC）一致。

```
GPIO15 (网名 MODEM_RXD) ←── U3脚18（模组发）  ⇒ GPIO15 是 ESP32 的 RX
GPIO16 (网名 MODEM_TXD) ──→ U3脚17（模组收）  ⇒ GPIO16 是 ESP32 的 TX
```

接反没有任何报错，就是收不到数据。照 `board.h` 写即可（已按实测对齐）。

### ② PWRKEY 经 Q2(MMBT3904) **反相**
**GPIO17 拉【高】才是开机触发。** 写成拉低的话，现象是"完全没反应"，无报错。

查法：
1. 量 GPIO17，固件置 1 时应为 3.3V
2. 量 Q2 集电极（MODEM_PWRKEY_N），GPIO17 高时这里应接近 0V
3. 都对还不开机 → 量 U3 的 42/43 脚有没有电
4. **4G 模组开机瞬间电流可达 2A** —— 只用 USB 供电常常起不来，**插上电池再试**，这条经常是真凶

### ③ `MODEM_RESET_N` 没接 GPIO
模组死机只能靠 PWRKEY 长按 12 秒。下一版改板补上。

### ④ IO45 是 VDD_SPI 选压脚
上电被拉高会让 flash 供电变 1.8V，直接启动失败。板上它是悬空的，量到高电平说明有漏电或搭锡。

## 3.6 云端现状

`cloud/`，TypeScript / Node 20+，`tsc --noEmit` 0 错误、构建通过。

**三条核心规则已落进代码，不要改错：**

1. **分级由 `KIND_TIER` 查表决定，不采信模型输出。** LLM 只判动作类型和置信度 ——
   让模型自己输出级别，某次幻觉就是一条发出去的消息，不可逆
2. **置信度分流**：≥0.85 双通道 / 0.6~0.85 只飞书 / <0.6 不推。
   设备端弹卡片是"打断用户"，成本很高。宁可漏，不可错
3. **30 秒唤醒窗口是硬约束**。设备上传完只醒 30 秒，之后 4G 进 PSM，
   下次能收推送要等一个 TAU 周期（默认 1 小时）

**待接入**：ASR 供应商、持久化（现在是内存 Map，重启即丢）、确认后的实际执行、
飞书回调签名校验、设备鉴权。

配置：复制 `cloud/.env.example` 为 `cloud/.env` 并填入凭证。
