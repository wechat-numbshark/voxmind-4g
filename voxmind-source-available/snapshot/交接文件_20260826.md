# 第一部分：现状

## 1.1 产品是什么

**VoxMind —— 4G 联网的随身 AI 语音终端。**

核心主张是「**说完即办**」：用户对着设备说话 → 云端边转写边识别意图 →
屏幕弹出确认卡片 → 按一个键就在飞书里建好任务。

典型流程（会议中没网的场景）：

```
录音（本地存 NAND）→ 进入有网区域 → 上传 → 云端 ASR + 意图抽取
  → 双通道推卡片（设备屏幕 + 飞书机器人）→ 用户在任一边确认 → 执行
```

产品需求的权威版本是 `VoxMind_交接包_20260824/VoxMind_00b_产品需求_v3_20260825.md`，
里面的**三级动作分类 / 双通道确认 / 置信度分流 / 30秒唤醒窗口**是整个系统的地基，
固件和云端都是照它实现的。

## 1.4 DRC 现状

```
连接错误 (Connection Error)  0
间距错误 (Clearance Error)   0
网表标志 (Netlist Error)     1  ← 陈旧标志位，不影响，见下
```

那条 `Netlist Error: Import Changes` **是假阳性**，已确认：

- 原理图 456 个引脚 vs PCB 456 个焊盘，网络分配**零差异**
- 打开「设计 → 从原理图导入变更」对话框，列出的动作**全是「修改属性」**，
  没有任何增删元件/网络/导线 —— 这本身就证明网表一致

**⚠ 不要点「应用修改」。** 它会把 PCB 上的 `值=10uF`、`供应商封装=0805`、
`耐压`、`嘉立创库类别`、`数据手册` 等属性**清空**（因为原理图符号没带这些属性，
同步等于拿空的覆盖有值的），而这些正是下单贴片时 BOM 要用的字段。
**这条标志位不影响出 Gerber、不影响下单，留着即可。**

## 1.6 云端现状

`cloud/`，TypeScript / Node 20+。**`tsc --noEmit` 0 错误，`tsc -p` 构建通过**
（`strict` + `exactOptionalPropertyTypes` + `noUncheckedIndexedAccess` 全开）。

**为什么是 TypeScript 不是 Python**（决策记录，避免接手后又推翻）：

决定性因素是 **ASR 走云 API 而非自建**。Python 在本项目唯一的硬优势是语音 ML 生态
（FunASR / faster-whisper 只有 Python 绑定），但这个阶段不该自建 ASR——
中文识别用阿里云/腾讯云/讯飞 API 的准确率高于自建 Whisper，且不用养 GPU。
**ASR 一旦走 API，Python 优势归零**，剩下全是 I/O 编排（Node 主场）。

另外两条：`src/types.ts` 成为**设备·云端·飞书三方的唯一契约**，
协议改动在编译期就能发现；飞书有**官方** Node SDK。

**代价（已知）**：以后要做自建/端侧 ASR 或音频 ML，需单独起 Python 微服务用 HTTP 接入。

三条核心规则已落进代码，**不要改错**：

1. **分级由 `KIND_TIER` 查表决定，不采信模型输出。**
   LLM 只判动作类型和置信度。让模型自己输出级别，某次幻觉就是一条发出去的消息，不可逆。
2. **置信度分流**：≥0.85 双通道 / 0.6~0.85 只飞书 / <0.6 不推。
   设备端弹卡片是"打断用户"，成本很高。宁可漏，不可错。
3. **30 秒唤醒窗口是硬约束。** 设备上传完只醒 30 秒，之后 4G 进 PSM，
   下次能收推送要等一个 TAU 周期（默认 1 小时）。ASR + 意图抽取跑不完就只推飞书。

**待接入**：ASR 供应商、持久化（现在是内存 Map，重启即丢）、确认后的实际执行、
飞书回调签名校验、设备鉴权。

## 1.7 采购与装配现状

**如果下单勾选 SMT 贴片：45 种元件全部贴好**，BOM 每项都有立创货号。

**一个例外**：`J1` 电池座（PH-3AW）是**插件(THT)**，标准 SMT 不贴。
另选"插件贴装"或自己焊（3 个脚）。

**需要自己买并插上的五样**（都是连接器插接，**不用焊**）：

| 件 | 接到 | 规格 |
|---|---|---|
| 屏幕模组 + 排线 | J5 | 2.0" 240×320，ST7789 系 SPI + CST816 系 I2C 触摸。**脚序对不上，见下** |
| 锂电池 | J1 | 3.7V 带保护板，PH2.0 **三脚**插头，1000~2000mAh |
| 振动马达 | J6 | PH2.0 两线，3V 扁平马达 |
| 4G 天线 | J7 | **IPEX/U.FL 一代**接口的 LTE 天线（别买二代四代） |
| Nano SIM 卡 | J4 | 物联网卡或手机卡 |

**屏幕的真实情况**：J5 的脚序是设计时自定的——

```
1=3V3  2=GND  3=SCLK  4=MOSI  5=CS  6=DC  7=RST  8=BL  9=SDA  10=SCL  11=TP_RST  12=TP_INT
```

而现成模组（微雪 2inch、中景园 2.0寸）用 15PIN 端子 / 18PIN FPC / 12PIN 0.7mm 焊接，
**间距和顺序都不一样**。信号本身完全对得上，只是物理接口不同。

**首板过渡方案**：买模组 + 一根「GH1.25 12P 单头线」，按脚序表把散线焊到模组焊盘。
**DVT 正确顺序是：先定屏幕，再让 J5 迁就它的脚序**，这样能用现成排线。

**电池的坑（重要，上一轮写反过一次，已改正）**：

TI 数据手册原文：*"To disable the external temperature sense circuitry,
connect a 10-kΩ resistor from TS to VSS"*。
板上 `R4` 正是 10kΩ 从 TS 接地 —— **板子已是"禁用温度检测"配置**。

| 接法 | TS 阻值 | 结果 |
|---|---|---|
| 两线电池 / 三线但 NTC 悬空 | 10kΩ（只有 R4） | ✅ 正常充电，无温度保护 |
| 三线电池 NTC 直接接上 | 10k ∥ 10k = **5kΩ** | ⚠ 不再是禁用值，很可能判过温**停充** |

**要真正的温度保护**：**拆掉 R4**（0402），再用 10kΩ(103AT) NTC 的三线电池。

**⚠ 插电池前必须万用表量线序。** J1 是 `1=VBAT+ 2=GND− 3=TS`，
但电池插头线序各家不同，**接反烧板**。

## 2.1 环境与工具

### EasyEDA CLI

```bash
export E=/Users/neo/.local/bin/easyeda
$E health                      # 检查守护进程
$E daemon start &              # 没起来就启动，端口 60832-60841
```

**所有命令都要带 `--project VoxMind_EVT_V1`。**
**不要用 `--doc PCB1`** —— 文档名解析算一次"读"，在改动之后会被 `STALE_READ` 挡住。

### ⚠ zsh 不做词分割（踩过，浪费过时间）

```bash
P="--project VoxMind_EVT_V1"
$E pcb dump $P                 # ❌ zsh 里 $P 被当成【一个】参数，命令失败
$E pcb dump --project VoxMind_EVT_V1   # ✅ 直接写
```

Bash 会把 `$P` 拆成两个参数，zsh 默认不会。本项目的 shell 是 zsh。

### ⚠ 铁律 5：每次改动后必须 save → doc reload → 验证

```bash
$E pcb <任何改动命令> --project VoxMind_EVT_V1
$E pcb save --project VoxMind_EVT_V1
$E doc reload --project VoxMind_EVT_V1
$E pcb drc --project VoxMind_EVT_V1        # 用 DRC 验证，不要相信命令的返回值
```

**命令返回 `ok: true` 不代表改动生效。** 有实锤案例：
`pcb stackup set --plane 15`（把内层翻成内电层）**返回 ok:true 但层类型读回仍是 SIGNAL**，
这条命令实际不生效，是 EasyEDA SDK 的缺陷。

不 save+reload 就去读数据，会拿到空结果或 `STALE_READ`。

### ⚠ 每次加铜之后必须 pour-rebuild

```bash
$E pcb pour-rebuild --project VoxMind_EVT_V1
```

新加的过孔/走线不会自动让铺铜避让，DRC 会报一堆
`Copper Region to Via` / `Copper Region to Hole` 间距错误。重建铺铜就全消失。

### ⚠ 模态对话框会挡住 API

EasyEDA 里弹出对话框时（比如「确认导入信息」），**CLI 的读命令全部失败**
（返回 `EDA_CALL_FAILED / 获取所有器件失败`）。先把对话框关掉。

 "const f=await eda.pcb_ManufactureData.getPdfFile('X');

# 2) 分块取回（每块 ≤700000 字符）
$E debug exec --project VoxMind_EVT_V1 --code "return globalThis.__f.slice(0,700000)"

## 2.4 布线的六条经验（都是踩出来的）

### ① 布线失败先判可达性，不要调参数

布线器报"搜索超限"时**不要**先去调启发式权重、代价、步数上限。
先跑 `reach.py` 做硬判定：起点域和终点域是否相交。**不相交就是真不可达，调参没用。**

实锤：LCD_RST 的终点 J5_7 被困在只有 1171 格（约 0.005 in²）的口袋里，
在发现这点之前浪费了两轮去调内层代价（1e6 → 6.0 → 1.5）。

判定完接着用 `whatif.py` 做**拆除组合检验**，找最小拆除集。
LCD_RST 的答案是"拆 LCD_BL_PWM 或 MIC_DATA_1V8 任一条即可"，比盲目拆线精确得多。

### ② 先合岛，再打孔

修断线时**先看同网络的孤立点之间能不能直接连**，再考虑打过孔接铺铜。

实锤：11 个孤立 GND 点，逐点找孔位只成功 7 个且互相撞孔。
改成先合岛（U4_2↔U4_3↔U4_8↔C18_2 两条 12mil 短线、U7_2↔U7_5 一条 5mil 竖线），
**11 个错误直接掉到 6 个**，其中 U7 那对合完后自己碰上铺铜，两个错误凭空消失。

密集封装（0.5mm 间距）里同网络相邻引脚之间往往有干净通道——那里本来就不允许别的网络进来。

### ③ 过孔间距必须查【所有铜层】，且规则和导线不同

过孔是贯通的。本板 L16（内层2）上有 244 根信号走线，**只查顶底两层会漏判**，
DRC 事后才报 `Track to Via` / `Hole to Track`。

规则也不能套用导线的：

```
过孔↔导线 6.0    孔↔导线 6.9    孔↔孔 11.8
而 导线↔导线 只要 4.0
```

把过孔当"零长度粗导线"丢进 `geo.path_clearance` 会**低估 2~3 mil**。
**用 `viacheck.via_slack()`，不要用 `geo.path_clearance`。**

### ④ 包围盒预筛必须用线段包围盒，不能用端点距离

一根从 x=90 拉到 x=1289 的长走线，两个端点都离检查点几百 mil，但中间紧贴着它。
用端点距离预筛会**直接跳过**它。这个坑踩过两次。

```python
# ❌ 错
if abs(t['startX']-x) > box and abs(t['endX']-x) > box: continue
# ✅ 对
if (min(t['startX'],t['endX'])-box > x or max(t['startX'],t['endX'])+box < x or
    min(t['startY'],t['endY'])-box > y or max(t['startY'],t['endY'])+box < y): continue
```

### ⑤ `near_obstacles` 会跳过同网络对象

所以**同批次放的过孔互相看不见**，会放出相距 8mil 的两个孔。
孔↔孔 11.8mil 是**工艺规则，与网络无关**，必须单独对已放孔做中心距检查。

### ⑥ 布线顺序决定成败

**最短最受限的先布，铺铜次之，最能绕的最后。**
同一批次里布完一条要**立即登记为障碍**，而且要**同时写进 `maze` 和 `geo` 两边**——
`geo` 是独立校验器，用自己那份数据，只写 `maze` 会让校验看不见同批次的其它路径。

## 2.5 内电层转换不可用（替代方案）

`easyeda pcb stackup set --plane 15` **返回 ok:true 但层类型读回仍是 SIGNAL**，
加 `--layers 4` 也一样。这条命令实际不生效，是 SDK 缺陷。

**替代（已验证有效）**：内层1 保持 SIGNAL + 满板 GND 铺铜，孤立点就近打过孔接这层。
电气等价，但要逐点人工处理，且周围要留得下过孔（外径 24mil 需约 26mil 净空）。
布线器里把内层1 的步进代价设成 `1e6` 可以禁止信号走它
（`maze.py` 第 199 行，现在是 1.5，因为最后阶段放开了少量借道）。

区域1  x 1320.88~2109.12,  y   19.43~299.90   规则: no-fills, no-wires, no-pours, no-inner-electrical
区域2  x 1835.26~2164.74,  y 1324.76~1635.24  规则: no-pours, no-inner-electrical   ← 天线区，允许走线

## 3.2 做布局调整前必须知道的约束

**⚠ 任何器件移动都会作废阶段门，导致 `STAGE_BLOCKED`。**
需要重走：`pcb stage confirm-tier 1..4` → `layout-lint --gate` → `confirm-layout` → `confirm-outline`。

**⚠ 移动器件会毁掉现有布线。** 现在是 DRC 全零的状态，重排布局意味着
**大概率要重布相关区域**。建议：

1. **先备份**（GUI 另存 .eprj2 + `git commit`）
2. 用 `netgraph.py` 记录当前连通状态作为基线
3. 小步移动 + 每步 `drc` 验证，不要一次性大改
4. 布线失败时用 §2.4 的方法论（reach → wall → whatif），不要盲目调参

**结构硬约束（已知）：**

| 项 | 值 | 影响 |
|---|---|---|
| 最高件 C32（470µF） | 8×10mm，顶层 | PCB 1.6 + 10 = **11.6mm**，外壳顶面下限 |
| 板框 | 100 × 55mm | 器件占用率 39%，有腾挪空间 |
| 底层现有 13 件 | USB-C、SIM座、J8、Air780E、5 个按键 | 按键要上移到顶层，这几件的位置也要重新考虑 |
| 天线禁布区 | x 1835~2165, y 1325~1635 mil | 该区域不能铺铜、内层无铜 |
| USB-C(J2) / SIM座(J4) | 底层 | 都是**外部可及**的接口，位置受外壳开孔约束 |

**可以考虑的方向（未验证，供接手人判断）**：
把 C32（10mm 高的电解电容）换成更矮的封装或多颗并联的贴片钽电容/MLCC，
能显著降低外壳厚度。但要核算 ESR 和纹波，别为了薄牺牲电源稳定性。

## 3.3 「尽量贴片」的研究方向

**现在唯一的插件件是 `J1` 电池座（PH-3AW，THT）。** 其余 44 种全是 SMD。

可以研究的替换：

| 件 | 现状 | 可能的贴片方案 | 风险 |
|---|---|---|---|
| **J1 电池座** | PH-3AW，**THT** | 换 PH2.0 的 **SMD 卧贴/立贴版本**，或换 JST GH/SH 系 SMD 座 | 换座子=换封装=改原理图+PCB，且要重新确认线序 |
| **天线 J7** | U.FL 座**本身已经是 SMD** | 用户要买的是**外接天线**。若想完全免外接：换**贴片陶瓷 LTE 天线**或**PCB 板载天线** | ⚠ **LTE 频段低（700MHz~2.6GHz），贴片天线效率远低于外接天线**，会明显影响信号。EVT 不建议动 |
| 屏幕 | 排线插接 | 无贴片方案（屏幕本来就是模组） | — |
| 马达 | 排线插接 | 有 SMD 马达但需要重新设计安装结构 | — |
| 电池 | 插接 | 无 | — |

**交接人的判断**：
- **J1 换 SMD 座是值得做的**，成本低收益明确（省一次手工焊接）
- **天线不建议动**。U.FL 座已经是贴片，用户实际要焊的东西是零。
  换板载天线会牺牲 4G 信号质量，而信号是这个产品的命脉（"有网了马上处理"）。
  如果确实想去掉外接天线，那是 DVT 阶段配合射频测试做的事，不该在 EVT 拍板。

## 附：四个会烧掉一整天的硬件坑（详见 docs/10）

1. **`MODEM_RXD` 是模组视角命名** —— 对 ESP32 而言是 **TX**。接反没有任何报错
2. **PWRKEY 经 Q2(NPN) 反相** —— GPIO 拉**高**才是开机。写成拉低，现象是"完全没反应"
3. **`MODEM_RESET_N` 没接 GPIO** —— 模组死机只能靠 PWRKEY 长按 12 秒
4. **IO45 是 VDD_SPI 选压脚** —— 上电被拉高会让 flash 供电变 1.8V，直接启动失败

第五条在 docs/13：**电池买两线，或买三线但拆掉 R4**（见 §1.7）。
