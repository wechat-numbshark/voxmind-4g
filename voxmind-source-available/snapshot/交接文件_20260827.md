# 第一部分：需求与现状

## 1.1 产品是什么

**VoxMind —— 4G 联网的随身 AI 语音终端。核心主张「说完即办」。**

不是"录得清楚"，而是把开会说的话直接变成系统里的事：

```
说话 → 本地录音存 NAND → 有网时上传
    → 云端 ASR 转写 + LLM 抽取意图
    → 双通道推确认卡片（设备屏幕 + 飞书机器人）
    → 按一下 OK → 云端用 lark-cli 真的建好飞书日程/任务
```

**设备是"瘦终端"**：只负责录音、存储、联网、显示卡片、按键确认。所有智能在云端，
硬件简单、能力可热升级。面向**超级个体 / 项目管理者 / 小团队**。

权威需求：`VoxMind_交接包_20260824/VoxMind_00b_产品需求_v3_20260825.md`
（三级动作分类 / 双通道确认 / 置信度分流 / 30 秒唤醒窗口 是整个系统的地基）

### ⚠ 三处与需求文档不符（发现于核验，需你确认）

1. **SIM 卡座是 Micro-SIM（3FF），不是 v3 需求写的 Nano-SIM**
   实际件：`MICRO SIM 6P H1.35`（C7529380）17.6×18.4mm；需求要的是 Nano 翻盖式约 13×11.5mm。
   **影响已消除**：物联网卡都是三合一切割卡（大卡 25×15 / Micro 15×12 / Nano 12.3×8.8），
   掰成 **Micro 尺寸**直接插。买卡时挑「三合一/三切卡」，别买贴片卡（MFF2）。

2. **内层2 上跑了 278 根非 +3V3 信号**，v3 需求写的是"+3V3 平面（可走少量信号）"。
   会让 +3V3 平面碎片化。内层1（GND）只有 3 段线，是干净的完整地平面 ✅。

3. **屏幕从 1.69"/240×280 漂移到 2.0"/240×320**。
   硬件都能用（同为 ST7789 + CST816），但 `01_产品原型` 里的卡片 UI 是照 240×280 画的，
   **LVGL 布局要重排**（长宽比不同）。

## 1.4 三根飞线（板子回来要焊）

| # | 网络 | 起点 | 终点 | 长度 | 必要性 |
|---|---|---|---|---|---|
| 1 | **SIM_N4** | `R16` 内侧焊盘 (57.10, 19.94) 顶层 | 过孔 (68.53, 22.00) | 11.6mm | **必须** —— SIM 时钟，不接则蜂窝失效 |
| 2 | TP_RST | 铜岛 (39.02, 33.89) | 铜岛 (40.39, 27.18) | 6.8mm | 建议接 —— 触摸复位 |
| 3 | EN | 铜岛 (24.69, 18.95) | `J8_5` (35.61, 27.25) 底层 | 13.7mm | **可不接** |

坐标原点为板左下角。建议 0.1mm 漆包线，焊后点 UV 胶固定。

**第 3 根可不接的原因**：EN 主块 `U2_3 + R5_1 + C10_1 + SW5_1` 已完整连通 ——
复位有上拉、去耦、SW5 按键。断的只是 J8 那一路，复位可用 SW5 或 USB 原生复位。

### 为什么消不掉（逐条硬判定，不是经验判断）

方法：`reach.py` 可达性 → `wall.py` 找围墙 → `whatif.py` 拆除组合 → **完整 MST 恢复验证净收益**。

> **「净收益」是关键概念**：拆掉 A 能让 B 通，但 A 自己布不回来 = 拆东墙补西墙。
> 必须把拆掉那条网络的**全部焊盘**重新连通才算数，不能只看能不能到达。

| 飞线 | 试过的方案 | 净收益 |
|---|---|---|
| **SIM_N4** | 拆 SIM_N2 | −1（SIM_N2 只恢复 1/3） |
| | 拆 SIM_VDD | 0（SIM_VDD 恢复 4/5） |
| | 拆 SIM_CLK | 0（SIM_CLK 恢复 0/1） |
| | R16 平移 4 个候选位 | 更差（口袋从 2864 格缩到 274 格） |
| | R16 旋转 90°/270° | 两条网络仍只能通一条 |
| TP_RST | 拆 LCD_RST | 0（LCD_RST 恢复 0/1）——**两条都是 J5 的网络，互锁** |
| EN | 拆 I2C_SDA | 0（I2C_SDA 恢复 1/2） |

**SIM_N4 的根因**：R16 这个 0402 电阻的两个脚，在当前几何下**只有一个能逃出去**。
现在保 `SIM_CLK`、断 `SIM_N4`；反过来也一样。真正的解是重排 R16/R17/R18/R19 那一簇
（四个串阻挤在 x 53.8–61.2 / y 15.3–20.8，被 U2 模组和 SIM 座夹住）→ DVT 范围。

**已消除的一根**：`GPIO0_BOOT` 原判"不可布"，实为**目标焊盘选错** —— 选了 `J8_6`，
而 `J8_6` 自己困在 5051 格口袋里。换成同主块的 `R6_1` 直接通（2569mil / 4 过孔 / 余量 1.04），
**零代价，不需拆任何线**。教训见 3.6。

# 第三部分：操作技巧与坑

## 3.1 五条铁律

1. **`"ok": true` 不等于成功。** 要看 `"applied"` 字段。
   实例：`pcb modify --patch '{"layer":"TOP"}'` 返回 `ok:true` 但 `applied: []`、`unverified:["layer"]` —— 层根本没改。
2. **每次 mutation 后 `save` → `doc reload` → 用 `drc`/`via-list`/`track-list` 复核真实数量**，
   绝不拿命令返回值当依据。
3. **每次加铜必须 `pour-rebuild`**，否则陈旧铺铜会制造几十条假冲突。
4. **任何器件移动都作废阶段门**，不重签的话后续打孔布线会被 `STAGE_BLOCKED` **静默**拒绝
   （`power-planes` 曾报告打了 114 个过孔，实际一个都没落地）。
5. **zsh 不做词分割。** `for x in ${NETS//,/ }` 只会得到一个词。用显式列表或 `${=NETS}`。
   这个坑我在同一个会话里踩了两次。

## 3.3 出制造文件不用点鼠标

```bash
$E debug exec --project VoxMind_EVT_V1 --timeout 240 --code "<JS>"
```

API 在 `eda.pcb_ManufactureData` 下：`getGerberFile` / `getPickAndPlaceFile` /
`getBomFile` / `getPdfFile` / `getAltiumDesignerFile`。

**⚠ 响应有 1 MiB 上限**（PDF 1.7MB、Altium 870KB 都会截断）。分块写法：

```bash
# 1) 生成一次,base64 存进连接器全局变量(globalThis 跨调用保留,实测有效)
LEN=$($E debug exec --project P --timeout 300 --code \
 "const f=await eda.pcb_ManufactureData.getPdfFile('X');
  const b=new Uint8Array(await f.arrayBuffer()); let s='';
  for(let i=0;i<b.length;i+=8192){s+=String.fromCharCode.apply(null,b.subarray(i,i+8192));}
  globalThis.__pdf=btoa(s); return globalThis.__pdf.length")
# 2) 每块 ≤700000 字符取回,拼接后 base64 解码
$E debug exec --project P --code "return globalThis.__pdf.slice(0,700000)"
```

现成脚本：`.easyeda/an/fetch_mfg_v5.sh`（含 Gerber + Altium + PDF 的完整分块写法）

**解压 Gerber 时**：包内有个乱码文件名会让 `unzip` 进交互提示卡死。
用 `unzip -o pkg.zip "Gerber_*" "Drill_*" < /dev/null` 只取需要的。

## 3.4 原生自动布线可以纯 API 调用（重要）

CLI 没有这条命令，但 `eda.pcb_Document.autoRouting()` 可以直接调。参数表是从压缩源码里反推的：

```js
await eda.pcb_Document.autoRouting({
  layers: [1,2],                    // ⚠ 默认值是"所有启用的 SIGNAL/PLANE 层",会把内层1/2 也算进去!
  RoutingNets: ['NET_A','NET_B'],   // 或 'selected' / 'selectedComponents'
  existingPrimitiveMode: 'keep',    // 默认 keep,保留已有铜
  cornerStyle: 0,
  optimization: 0,                  // 0=完成度优先(实测比默认的 1 多布通 6 条)
  ignoreNets: ['GND','+3V3']        // 已铺铜的电源网必须忽略
})
```

**`layers` 不显式传就会布到内电层上** —— 这大概率是早期几轮把板子布烂的原因之一。

**以 `pcb drc` 的实际断点为准**生成作业，否则会生成一堆无用的活。

## 3.6 布线七条经验

### ① 失败先判可达性，不要调参
`reach.py` 做硬判定：起点域和终点域是否相交。**不相交就是真不可达，调参没用。**

### ② 目标焊盘选错会伪装成"不可布"
`GPIO0_BOOT` 判为不可布，实为选了 `J8_6` 作目标 —— 而 `J8_6` 自己困在 5051 格口袋里。
**换成同一连通块里的另一个焊盘（`R6_1`）就直接通了。**
→ 布之前先用 `netgraph` 看清主块里有哪些焊盘，挑最开阔的那个当目标。

### ③ 「净收益」必须用完整 MST 验证
拆网络后要把它的**全部焊盘**重新连通才算数。只恢复一条会漏判：
`ripsim_v5` 报"净收益 1/1"，改成完整 MST（`ripsim_v6`）后真实结果是 1/3。

### ④ 先合岛，再打孔
修断线时先看同网孤立点之间能不能直连。密集封装里同网相邻引脚之间往往有干净通道。

### ⑤ 过孔间距必须查【所有铜层】，且规则和导线不同
```
过孔↔导线 6.0    孔↔导线 6.9    孔↔孔 11.8    而 导线↔导线 只要 4.0
```
**用 `viacheck.via_slack()`，不要用 `geo.path_clearance`。** 内层2 上有 278 根信号，只查顶底会漏判。

### ⑥ 孔↔孔是工艺规则，与网络无关
同批次放的过孔互相"看不见"（`near_obstacles` 跳过同网对象），会放出相距 8mil 的两个孔。
必须单独对已放孔做中心距检查。

### ⑦ 布线顺序：最短最受限的先布，铺铜次之，最能绕的最后
布完一条**立即登记为障碍**，且要**同时写进 `maze` 和 `geo` 两边**。

## 3.8 DRC 与 check 的差异（别被 64 个 ERROR 吓到）

`pcb check`（自研 DFM 审计）报 64 ERROR，但：

| 类别 | 数量 | 判定 |
|---|---|---|
| clearance | 41 | **假阳性**。检查器用统一 6mil 在量，板子实际规则是 `Track↔Track = 0.10199878mm = 4.02mil`（`Safe Spacing / copperThickness1oz` 表第一行）。实测最小 4.50mil > 4.02mil，且远高于嘉立创 3.5mil 工艺下限。**原生 DRC 报 0**。 |
| silkscreen-flipped | 23 | **真问题但只影响外观**。是每个器件旁印的封装名（`C0402` 之类），不是位号。量产板本就不该印。修法：EDA 里选中器件关闭「封装」属性显示 —— **agent API 改不动**。 |

**原生 `pcb drc` 是制造判据**，`pcb check` 是补充审计，两者模型不同。


## 3.12 六层实验：加层【不能】消除飞线（2026-08-28 实测，勿重走）

有人会想"加两层不就有地方走线了吗" —— 我完整试过，**结论是不行**，别再花时间。

**好消息：改叠层是无损的。** `pcb stackup set --layers 6` 之后：
```
tracks 2015 → 2015    vias 389 → 389    pours 4 → 4    DRC 7 → 7   间距 0
```
现有布线一段不丢，凭空多两个空信号层。6→4 改回来同样无损。

**坏消息：三根飞线一根都没消掉。**

| 尝试（全部在 6 层下） | 净收益 |
|---|---|
| 拆 SIM_VDD → 布 SIM_N4 | 0（SIM_VDD 恢复 4/5） |
| 拆 SIM_N2 → 布 SIM_N4 | −1（恢复 1/3） |
| 拆 LCD_RST → 布 TP_RST | 0（恢复 0/1） |
| 拆 I2C_SDA → 布 EN | 0（U5_8 真不可达，域仅 519 格） |
| 搜索上限 250万 → 2000万步 | 单条跑 >1 小时未收敛 |
| 0.2mm 小过孔 | 只救回 TP_RST，且要加严工艺 |

**为什么没用（关键洞察）**：加层增加的是**空旷区**的走线空间，但这三根卡在**焊盘周围最后 30mil**。
实测三个焊盘的可用净空是 **30.3 / 37.4 / 28.1 mil**，而标准 24mil 过孔只需要 18mil ——
**空间本来就够**。卡住的是"从焊盘走出去的通道"，通道两侧是 R16 自己的另一个脚、
R18/R23 的焊盘 —— **这些加多少层都不会消失**。

**真正的解仍然是**：重排 R16/R17/R18/R19 那一簇（DVT）。

### 顺带修的两个工具 bug（已改进代码，勿回退）
- `autoroute2.py` 的复核写死 `od=24.0, hd=12.0`，改过孔尺寸后规划器和复核器模型不一致，
  复核全是负余量 → 已改成 `od=maze.VIA_OD, hd=maze.VIA_HD`
- 测试时**一次只改一个变量**：我同时改了层数和过孔尺寸，误以为"必须用 0.2mm 小孔"，
  分离变量后才发现标准孔空间就够


## 3.13 v7 改版：三个连接器换型 + 定点重排（2026-08-28）

目标：**零飞线 + 屏幕直插**。做法不是"加层"也不是"放大板子"，而是换掉三个连接器再做定点手术。

### 换掉的三个件（EDA 库里都有现成封装，`easyeda lib by-lcsc` 可查）

| 位号 | 旧 | 新 | LCSC | 换它的理由 |
|---|---|---|---|---|
| **J2** | USB3.1TYPE-C16P（纯贴片固定） | 首韩 TYPE-C16PIN | **C393939** | 旧件只靠 4 个贴片外壳焊盘受力，定位孔还是**非金属化**的（不承力）。新件 **4 脚插板 + 1万次插拔寿命**，库存 43 万+，¥0.40 |
| **J4** | MICRO SIM 6P（17.55×17.23mm） | 星坤 NANO_SIM | **C9900014790** | 需求本来就要 Nano；**省出 6.8×5.3mm**，正是 J5 装得下的关键 |
| **J5** | BM12B-GHS-TBT 12P 自定脚序 | JST BM15B-GHS-TBT 15P | **C20089180** | 微雪 2inch 屏配的就是 15PIN GH1.25 带锁扣排线，**直接插，12 根手焊线全免** |

**⚠ 三个都是「SMT 扩展库」**，嘉立创贴片会收一次性上料费。基础库里没有等效的加固 USB-C 和 Nano 座。

### 换件的正确姿势：`sch replace`，不要走 §3.9 那套

§3.9 记的手工流程（disconnect → prim-delete → place → connect 逐脚）已被 `sch replace` 取代：

```bash
easyeda sch replace --project <P> --doc <页> --id <primitiveId> --lcsc C393939
```

它保留位号和 **uniqueId**（所以 PCB 端是**更新**封装而非删了重加），失败自动回滚，并返回 **pinDiff** 告诉你哪些脚对不上。

**踩过的三个坑**：
1. **警告文字打在 JSON 前面**，直接 `json.load` 会炸。先找第一个 `{`。
2. **replace 会换掉 primitiveId**。第一次调用成功后，用旧 id 再调一次必然报
   "No schematic component found" —— 这不是失败，是你已经成功了。
3. **旧桩线会变成孤儿树**（不是短路，也不是悬空桩）。用 `sch bridge-check` 找出来，
   `sch prim-delete` 清掉，再用 **`sch autoconnect`** 重接。

### `sch autoconnect` 是重接线的正确工具

比 `sch connect` 强得多：它给每个候选方向打分，**硬拒"穿过非目标引脚"的方案**——
正是 §3.9 记的"桩线共线合并短路"那个坑的解药。而且支持按功能名批量绑定：

```bash
easyeda sch autoconnect --pin "J2:GND*"   --kind gnd     --net GND       # A1B12+B1A12 一起
easyeda sch autoconnect --pin "J2:SHELL*" --kind gnd     --net GND       # 4 个外壳脚一起
easyeda sch autoconnect --pin "J2:VBUS*"  --kind netport --net VBUS_RAW  # A4B9+B4A9 一起
```

### 定点重排（不要用全局 auto-place）

**全局 `pcb auto-place --assembly-gap 50` 是个陷阱**：它确实把三个关键间隙修好了，
但同时制造出 **25 短路 / 18 重叠 / 3 个元件跑到板外**（把 C14/C15 直接摞在 U2 焊盘上），
而 `pcb refine` 明确**不修**短路/重叠/板外。

正确做法是**只动真正卡住的那两个元件**，位置用全局搜索选：

```
R16  (57.53,19.94) → (55.60,20.37)   净空 7.5 → 35.7 mil   位移仅 1.9mm
J8   (37.49,28.92) → (43.61,12.90)   净空 8.4 → 80.6 mil   顺带挪到 U2 正下方，信号更短
J5   → (45.0,50.0) 板子上边缘并锁定   净空 25.6 → 55.5 mil
```

搜索方法：网格扫全板，要求该元件**每个焊盘四周 ≥25mil 无异网铜**，再按信号总长排序。
R16 有 12520 个合格位，J8 有 1146 个 —— 死结一旦松开，选择余地是很大的。

### 又两个"报成功但没生效"的命令（补充铁律 5）

| `pcb delete` | 对走线/过孔返回 `deleted:true` 但**什么都不删**（它只管 component primitives） | 用 `pcb track-delete` / `pcb via-delete` |
| `pcb dump` | `doc reload` 之前会**静默返回旧快照**，害我误判 J5 没移动 | 任何 mutation 后先 `doc reload` 再 dump |

## 3.9 J5 换 15P 失败记录（DVT 必读）

**原理图那部分成功了**，PCB 装不下。存档在 `VoxMind_EVT_V1_v6_J5_15P_FAILED_*.eprj2`，
DVT 重排时可直接拿来接着做，省一半工。

**做法**（可复用）：
1. `sch disconnect --pin J5:N` 逐个断开旧脚（14 个）
2. ⚠ `sch rebind-symbol` **不可用** —— 报 "read-only library record, no personal library for clone fallback"。
   改用 `sch prim-delete` + `sch place --lib … --uuid … --designator J5`
3. `sch connect --pin J5:N --net XXX --kind power|gnd|netport` 逐脚接线
4. ⚠ **桩线会共线合并短路**：pin3 的 GND 桩线把 pin4/5/6 一起吞了。
   用 `--direction left --offset 40/60/80` 错开
5. `sch no-connect --designator J5 --pin 4,7`（注意是 `--designator` + `--pin`，不是 `--pin J5:4`）
6. `sch bridge-check` 确认 0 短路 0 孤儿
7. `pcb import-changes` → `pcb modify --center` 落位

**失败原因（几何硬判定，非布线器能力问题）**：

```
12P 旧件 18.6mm   →   15P 新件 22.31mm   走廊只有 23.1mm（左邻 R7、右邻 U8）
→ 两侧各剩 0.4mm，引脚逃逸通道被挤没
→ LCD_DC / LCD_MOSI 的 J5 焊盘困在 900~1000 格口袋里,硬判定不可达
→ 27 条布线作业失败 16 条
```

全板搜索：既在屏幕模块区内（x30–88.8）、又有 1.2mm 逃逸空间的位置有 375 个，
但**最近的一个离信号重心 32mm** —— 12 条 LCD/触摸信号都要横穿板中拥挤区。

**结论：15P 要装进去，必须重排 J5 周边整片（R7 / U8 / U6 / C27 那一簇）。**

**另一条值得试的路**：模块也提供 **18PIN FPC 0.5mm** 接口。
18P×0.5mm 的 FPC 座只有约 11~12mm 长，**比现在的 12P GH（18.6mm）还小**，
装得下且能腾出空间。缺口是**微雪没公开 18P FPC 的脚序**，需要买到模块后实测或问客服。

### 关键教训

**1. 「JLCPCB Assembly」占位条目 ≠ 真实目录条目**
J4 挂的是 `C9900014790`（库存 0），而 XKB 原厂目录里 **同一个型号** `C2931483` 有 2056 库存。
J5 同理：`C20089180` 是 0，`C5305069`（同型号 LF/SN 后缀）有 2612。
**缺货时先搜 MPN 找真实目录条目，再考虑换型号。**

**2. 换件必须交叉比对多家封装 —— 抓到一个致命隐患**
旧 U9 封装 `LGA-8_L8.0-W6.0-P1.27` 是错的：9 焊盘、脚 1 在顶部中央，
相对 MK/创世纪/天微三家的封装**互为镜像**。按它贴片 SD_CS 会落到芯片 VCC 脚。
方法：`pcb add-component` 把候选封装临时放到板外空白处 → `pcb dump` → 比对相对坐标 → 删掉。

**3. 背面器件的旋转会叠加镜像**
J8 在层 2。rot180 只翻 X 不翻 Y；rot0 才让信号排/固定脚回到正确一侧，但脚号顺序反转。
**解法不是继续转，而是反转原理图接线**（1↔6, 2↔5, 3↔4）——
物理焊盘的网络与换件前逐一相同（偏差 6.9mil），走线零改动。
**做任何间距/位置判断前先看 `component.layer`，否则会误报**（我一度以为 SIM_N2 压住了 U3_100，
实际一个在层1 一个在层2）。

**4. `pcb via` 不带直径参数 → 按板规默认建成 24mil**
布线器按 20mil 验算，差这 2mil 会把余量吃成负数。
建完必须 `eda.pcb_PrimitiveVia.modify(id,{diameter:20})` 改回来。

**5. BOM 的 LCSC 编号取自 PCB 侧 `supplierId`，不是原理图**
`sch resolve-lcsc` 报 `via:instance`（原理图有编号）但 BOM 仍缺 23 项。
`pcb sync-attrs` 补不了（它需要先有 LCSC 才能查库）。
正解：`eda.pcb_PrimitiveComponent.modify(id,{supplierId:'Cxxxx'})` 批量写，71 个一次搞定。

**6. `pcb.components.list` 失败先查活动文档是不是 PCB**
报 "Failed to list PCB components" 时，大概率是当前活动文档切到了原理图。
`easyeda project open --uuid <pcbUuid>` 切回来即可，不是守护进程坏了。

**7. `pcb check` 的 floating-track-island 会误报 T 型搭接**
它和我的 reach 工具都是端点式锚定，看不见"支路从主干中段引出"（距端点 9mil）。
按**真实铜面重叠**重算（中心距 < 两半宽之和）才准 —— SD_MISO/UART0_RXD 两处均为误报，
EDA 自己的网表检查对它们没报断连。

**8. `reach.py` 命令行入口有差一错误**
它把目标名拼成 `trkE`+前 6 字符，而 `conn` 端是 `trk`+`E<目标名>`前 6 字符。
目标是焊盘（`U9_5`，4 字符）时刚好相等，目标是 `via…`/`trk…` 就 KeyError。
绕过：直接调 `reach.analyse()`，自己拼名字；且 `escape.best_stub` 只对焊盘有效。

### 遗留（3 条 DRC，均为既定）

1. `MICROSD_N5` 开路 —— U9 脚7 (SD DAT1) 上拉。SD-SPI 模式下 DAT1 闲置，规范允许悬空。
   硬可达性判定：该脚逃逸域仅 498~577 格，被 SD_MISO（真信号）占用的通道封死。
   唯一替代是撕内层 LCD_CS，不划算。DAT2 那路的上拉已布通。
2. `Netlist Error` —— **假的**。逐脚核对：两侧各 455 引脚、74 张网、0 差异、集合相同。
   `import-changes` 报"已应用无变更"但标记不清，需在界面点一次「导入更新」。
3. C38/C39 标 DNP —— LTE 天线 π 型匹配预留位，默认不焊。
