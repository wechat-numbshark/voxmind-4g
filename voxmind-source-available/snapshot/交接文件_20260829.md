## 2.2 纠错一：4G 串口引脚方向写反了（会让 4G 完全不通）

复核硬件坑时发现的。实测（在活原理图上直接读模组符号的脚名，两家模组一致）：

| 模组脚 | Air780E | ML307C-GC | 方向 |
|---|---|---|---|
| 17 | `MAIN_RXD` | `UART0_RXD` | 模组**收** |
| 18 | `MAIN_TXD` | `UART0_TXD` | 模组**发** |

接线是 `MODEM_TXD = GPIO16 ↔ 脚17`、`MODEM_RXD = GPIO15 ↔ 脚18`。模组在脚 18 上发，所以：

```
GPIO15（网名 MODEM_RXD） <-- U3脚18（模组发）  =>  GPIO15 是 ESP32 的 RX
GPIO16（网名 MODEM_TXD） --> U3脚17（模组收）  =>  GPIO16 是 ESP32 的 TX
```

**网名是 MCU 视角命名的，不是模组视角。** 旧文档反着理解，得出「GPIO15 是 TX」，
并把错误一路带进了 `board.h` / `gen_board_h.py` / `drv_modem.c`。
照错误版本编译，4G 串口完全不通**且没有任何报错**。

已在 8 个文件里全部改正（含生成脚本，重跑不会再生成错的）：
`board.h`、`gen_board_h.py`、`drv_modem.c`、`drv_modem.h`、
`docs/10_硬件接线真值表.md`、`README.md`、`firmware/README.md`、`交付/全流程指导`。

> **教训**：网表只告诉你「哪两个脚连在一起」，**不告诉你方向**。
> 方向只能来自器件符号或数据手册的脚名。把网名当方向依据是循环论证。

## 2.3 纠错二：撤销“脚100接地即可使用3.3V串口”的错误推断

8 月 29 日曾错误地沿用 Air780E 的脚100接地方式，并据此推断 ML307C 可与 ESP32 3.3V GPIO 直连。该推断已经被 ML307C 硬件手册否定，**不得恢复**：

- ML307C 脚100是 `RSV`，当前原理图标记 No Connect、PCB不连接。
- ML307C `UART0_RXD`、`UART0_TXD`、`DTR`、`STATE`、`VDD_EXT` 属于1.8V域。
- 当前工程通过 U10/U11 `SN74AXC2T45DCUR` 完成1.8V↔3.3V转换，方向定义见第0节。
- `MODEM_VDD_EXT` 只作为ML307C侧逻辑电源/参考与去耦使用，不得与板上 `+1V8` 或 `+3V3` 短接。

## 2.4 顺带挖出的一个致命隐患

旧 U9 封装 `LGA-8_L8.0-W6.0-P1.27` 有 9 个焊盘、脚 1 单独在顶部中央，
**相对 MK / 创世纪 / 天微三家厂商的封装互为镜像**。按它贴片，
`SD_CS` 会落到芯片的 `VCC` 脚上 —— **那颗存储芯片本来就不可能工作**。
换件时用「探针法」交叉比对三家封装才发现（见 4.3）。

# 第四部分：工具链与铁律

## 4.1 五条铁律（原样保留，仍然成立）

1. **`"ok": true` 不等于成功。** 要看 `applied` 字段。
2. **每次 mutation 后 `doc reload` → 用 `drc`/`via-list`/`track-list` 复核真实数量**，
   绝不拿命令返回值当依据。
3. **每次加铜必须 `pour-rebuild`**，否则陈旧铺铜会制造几十条假冲突。
4. **任何器件移动都作废阶段门**，不重签的话后续布线会被 `STAGE_BLOCKED` **静默**拒绝。
5. **zsh 不做词分割**。用 `${=VAR}` 或显式列表。

## 4.2 今天新增的六条

6. **缺货先查真实目录条目。** 「JLCPCB Assembly」是占位条目常年 0 库存，
   同一个 MPN 的厂商目录条目往往有大量货。换条目是零改动，换型号要重布线。

7. **换件必须交叉比对多家封装。** 用 `pcb add-component` 把候选临时放到板外空白处
   （y=3000+，间距 1500mil），`pcb dump` 比对**相对器件中心的焊盘坐标**，再 `pcb delete`。
   三家一致、只有一家不同 —— 不同的那家就是错的。
   ⚠ `add-component` 要求 **PCB 是当前活动文档**，否则报
   `Cannot read properties of null (reading 'attrsMap')`。

8. **背面器件的旋转叠加了镜像。** J8 在层 2：rot180 只翻 X 不翻 Y。
   转不出想要的朝向时，**改反转原理图接线**，让每个物理焊盘拿回原网络（走线零改动），
   而不是继续转。做任何间距判断前先读 `component.layer` / `pad.layer` ——
   不同层的铜不构成冲突（我一度误报 SIM_N2 压住 U3_100，实际一个层1 一个层2）。

9. **`pcb via` 不带直径参数 → 按板规默认建成 24mil**，而布线器按 20mil 验算，
   差这 2mil 会把余量吃成负数。建完必须
   `eda.pcb_PrimitiveVia.modify(id,{diameter:20})` 改回来。

10. **BOM 的立创货号取自 PCB 侧 `supplierId`**，不是原理图。
    `sch resolve-lcsc` 报 `via:instance` 也没用，`pcb sync-attrs` 更补不了
    （它要先有 LCSC 才能查库）。正解是批量写 PCB 器件：
    ```
    easyeda debug exec --project <P> --timeout 240 --code "
    const list = [[primitiveId,'Cxxxx'], ...]; let ok=0;
    for (const [id,c] of list) { await eda.pcb_PrimitiveComponent.modify(id,{supplierId:c}); ok++; }
    return ok;"
    ```
    24 个一批，71 个分 3 批一次成功。写完 `doc reload` 再重出 BOM。

11. **`pcb.components.list` 报错先查活动文档是不是 PCB。**
    "Failed to list PCB components" / "no connected window" 时，大概率是切到了原理图，
    `easyeda project open --uuid <pcbUuid>` 切回即可，不是守护进程坏了。

## 4.3 自研工具链（`.easyeda/an/`）

`maze.py` 迷宫布线 · `reach.py` 可达性硬判定 · `routegap.py` 单段布线 ·
`autoroute2.py` 批量作业 · `viacheck.py` 过孔余量 · `geo.py` 几何常量 ·
`conn.py` 网表对象化 · `apply_routes.py` 路径→CLI 命令 · `escape.py` 逃逸桩

**注意 `reach.py` 命令行入口有差一错误**：它把目标名拼成 `trkE`+前6字符，
而 `conn` 端是 `trk`+`E<目标名>`前6字符。目标是焊盘（`U9_5`，4字符）时刚好相等，
目标是 `via…`/`trk…` 就 KeyError。绕过：直接调 `reach.analyse()` 自己拼名字；
且 `escape.best_stub` 只对焊盘有效，走线/过孔目标不需要逃逸桩。

**`pcb check` 的 floating-track-island 会误报 T 型搭接** —— 它和 reach 都是端点式锚定，
看不见「支路从主干中段引出」（距端点 9mil）。按**真实铜面重叠**重算
（中心距 < 两半宽之和）才准。

# 附：硬件坑速查

上机手册有完整版（`交付/首板上机手册_v8.html`），这里只列标题：

1. **4G 串口方向** —— GPIO15 = ESP32 的 **RX**，GPIO16 = **TX**（旧文档写反过，见 2.2）
2. **PWRKEY 经 Q2 反相** —— GPIO17 拉**高**才是开机，写成拉低"完全没反应"
3. **`MODEM_RESET_N` 没接 GPIO** —— 死机只能长按 PWRKEY 12 秒
4. **IO45 是 VDD_SPI 选压脚** —— 上电被拉高 → flash 变 1.8V → 直接启动失败
5. **模组 IO 电平** —— ML307C 侧为1.8V，已由 U10/U11 转成 ESP32 侧3.3V（见第0节和2.3）
6. **J8 的 1 脚换到了另一端** —— 电气一致，但按丝印数脚会数反

② ③ ④ 已在 v8 板上逐条复验，结论不变。
