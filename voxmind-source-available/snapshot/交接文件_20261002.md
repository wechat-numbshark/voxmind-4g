## 1. 产品与现状

4G 随身 AI 录音设备：一直录音 → 每 5 秒一块上传 → 云端转文字、识别要办的事 → 明说的直接办（建飞书任务、记账、记笔记），
猜的弹卡片等确认 → 到点在设备屏上提醒。网页控制台看录音、任务、纪要、设置。

| 部分 | 现状（2026-10-02） |
|---|---|
| 设备 | ESP32-S3 + ML307C 4G + 2 寸 240×320 触摸屏 + 双 PDM 麦 + SD + 锂电。固件 1.0.0，USB 刷入，运行正常 |
| 录音上传 | 正常，采样 16000/s、丢失 0；断网本地缓存、联网补传 |
| 识别 | 百炼 DashScope：ASR `qwen3-asr-flash`，意图同一个 Key。飞书**正式模式**（`EXECUTION_MODE=live`） |

## 3. 日常操作

### 3.1 固件：编译、刷机

```bash
cd firmware
export IDF_TOOLS_PATH=$HOME/esp/idf-tools && source ~/esp/esp-idf/export.sh
idf.py -B build-cloud-current build
cd build-cloud-current && python -m esptool --chip esp32s3 -p /dev/cu.usbmodem3101 -b 460800 \
  --before default_reset --after hard_reset write_flash --flash_mode dio --flash_size 16MB --flash_freq 80m 0x20000 voxmind.bin
```

- 只刷 app 分区（0x20000）。设备若跑在 ota_1，要另写 `ota_data_initial.bin` 才会从新刷的 ota_0 启动。
- 串口 115200，`/dev/cu.usbmodem3101`（ESP32-S3 自带 USB）。设备关机（深睡眠）时这个口会消失，要用户长按录音键开机。
- 崩溃重启循环时 Mac 上的 USB 串口会卡死，只能让用户拔插一次 USB。
- 工具链曾在 `/private/tmp` 被系统清掉过，现在装在 `~/esp`，别装回 tmp。

### 3.2 串口调试命令（写一行回车）

| 命令 | 作用 |
|---|---|
| `screenshot` | 回传当前屏幕帧（用 `firmware/tools/screenshot.py 输出.png` 解，约 30 秒） |
| `pause` | 切换暂停/继续录音 |
| `page a` / `page b` | 切屏 |
| `shutdown` | 真关机（和长按录音键同一路径；之后要用户长按开机） |
| `demo card` / `demo feed` / `demo reminder` / `demo done` / `demo detail` | 本机造样例数据看界面，不写服务器 |
| `demo boot` / `demo off` / `demo sleep` / `demo clear` / `demo bright` | 开关机画面、亮度面板 |
| `demo talk 3000` | 模拟按住确认键 3000 毫秒（和真按键同一路径） |
| `radio test` | 照关机步骤退出拨号、关射频，但不真关；测完恢复 |
| `swipe partial` / `swipe full` | 翻页 30 次测帧率 |
| `power profile [秒]` | 耗电分段实验（要拔掉 USB 才作数），结果自动传到服务器 `vm_device_power_logs` |

- 设备每 30 秒打一条 `诊断:` 日志（采样率、丢失、4G、待传块数、内存），每 10 秒一条 `界面心跳`（停了＝界面冻住）。
- 已知：4G 连上后串口控制台偶尔不收命令，复位就好（只影响调试）。连续几条命令放在同一次串口连接里发。

## 4. 处理链路（排查"说了没反应"时按这个顺序查）

```
设备录音（5 秒一块，SD 卡落盘）
  → 上传 PUT /v1/device-sessions/:id/chunks/:seq        查 vm_audio_chunks 有没有这一块
  → 静音检测（transcript_status: pending→vad→speech/silent）
  → 相邻人声块拼一句转文字                                查 vm_transcript_segments
  → 意图判断（intent_status: pending→running→done/skipped）
  → 生成卡片：明说的直接执行，猜的等确认                  查 vm_action_drafts
  → 设备轮询 /v1/device-actions（1.5~4.5 秒）拿卡片/提醒；/v1/device-feed 拿回执和时刻表
```

- **按住说话**：设备在松手时把区间报给 `/v1/device-marks`。识别模式为"按住才识别"时，没标记的话只转写不分析。
  标记没到的新句子会等 20 秒；带标记的音频和句子在三处领活里都插队；命令整段已上传就立刻转文字。
- **暂停时**：不录周围声音，但按住确认键会单独录那几句（松手后多 1.5 秒）并插队上传。
- 2026-10-02 用户报"按住说了没反应"，真实原因是**当时处于暂停**（那时暂停时什么都不录）。先问状态再查。

## 5. 一定要知道的坑

### 5.1 硬件 / 固件
- **4G 模组电源键关不掉它**：按 1.5 秒、按住 12.5 秒 STATUS 都不掉，冷启动时它一直开着。怀疑上电即开机、
  PWRKEY 这条线从没起过作用。关机现在用 `AT+CFUN=0` 关射频，开机 `AT+CFUN=1`。**不要用 AT 把模组彻底关机**：
  电源键真不管用的话就再也开不起来，只能拆电池。要彻底断电得先用万用表量 Q2 集电极（docs/13）或改板。
- `esp_modem_set_mode(COMMAND)` 10ms 就报成功，紧跟着的第一条 AT 会被吞（20 秒无回复）：先发 `AT` 握手。
- ML307C 记住 `AT+IPR` 波特率，断电不丢；开机两种波特率轮流探。联网相关改动先 USB 实测再 OTA。
- **屏幕性能地板**：整屏重画一帧 40~50ms（画布在 PSRAM）。已试过且有害、别再试：SPI 超过 40MHz（联网后空白条/卡死）、
  运行时切换 LVGL 刷新模式（flush 回调回不来、冻屏）、滑动搬位图（不比重画快）。主频已是 240MHz。
- 深睡眠时背光脚、电源键脚会悬空：关机前都钉住并 `gpio_hold_en`，开机先 `gpio_hold_dis`。
- 设备字库只有 GB2312 + ASCII：「·」「✓」、emoji 显示成方块（服务端发给设备的文字会过滤，中点用「・」）。
- 界面改完必须真机截图（`screenshot` + `demo ...`）再说完成；LVGL `lv_obj_get_height` 读的是上一帧布局，刚改的高度读不到。
- OTA：云端和设备都拒绝降级；测完把推送范围设回 none，否则旧推送会把 USB 刷的新版"升级"回去。

### 5.2 云端
- `UserPrefs` 加字段：`domain.ts` 加默认值（zod 4 的 `.default({...})` 不会再填内层默认，整个对象字面量要写全）、
  `app.ts` 的 PUT /v1/settings 校验也要加，网页 `Settings.tsx` 的 `Prefs` 类型同步。
- 设备 HTTP 接收缓冲 3KB：心跳响应要 < 2KB（有测试盯着）。
- 主题颜色顺序：`themes.ts` 的 `THEME_ROLES` ↔ 固件 `ui_palette_t`，有测试逐个对照（导出目录里没有固件时该测试跳过）。
- 网页里 Hook 不能写在提前 return 后面（「我的」页面白屏过一次），`npm run lint` 会抓。

### 5.3 流程
- SSH 限流：连续多条命令会 "port 22 timed out"，加重试或等一会儿。
- 后台长时间等待用户操作（比如等开机）的脚本，超时设长一点（之前 1 小时超时过）。

### 5.4 测量
- 2026-09-20 查滑动卡顿连错三次，根子都在测量：基准走的不是用户真实路径（测成了瞬间跳页）、样本太少全是噪声、
  只在断网状态下测。先问：这个基准走的是不是用户那条路？样本够不够？系统状态和用户遇到问题时一样吗？

### 5.5 耗电（2026-10-02 实测，电池 1050mAh）
- 改之前：黑屏录音约 257mA（4 小时多就没电），暂停也有 193mA——暂停时 4G、轮询、CPU 都照常跑。
- 分项（拔线分段测，MAX17048 的 CRATE）：录音本身 64、亮屏轮询 24、4G 待机 28、CPU 240MHz 多出 33、面板+麦克风 29，
  剩下约 79mA 是底噪，还没拆开（怀疑 PSRAM / 4G 模组本体 / 稳压器静态电流）。
- 1.0.1 起的省电策略：亮屏 240MHz，黑屏录音 160MHz（80MHz 编码跟不上，丢过 7.4 秒音频），暂停 80MHz；
  黑屏面板 SLPIN；暂停时关麦克风（只能由采集任务自己关，主任务去关会和它抢 I2S 锁导致看门狗重启）；
  黑屏时 15 秒问一次服务器（亮屏 1.5 秒）；录音块默认 15 秒（后台可改 5/15），按住说话松手立刻收尾上传。
- 2026-10-03 拔线复测（1.0.2）：录音 150~235mA（约 5~6 小时）、暂停 90~170、暂停+轮询 60 秒 80~100、
  暂停+4G 射频关 70~90。**4G 射频加轮询只占约 20mA，关掉射频的暂停状态仍有 70~90mA**——下一步查 light sleep
  （`pm_update` 里 `light_sleep_enable=false`）、SD 卡、指示灯、4G 模组本体供电。两次跑差异大，CRATE 滞后，按区间看。
- **2026-10-03 晚 ~ 10-04 凌晨（1.0.4~1.0.10）**：
  - 编码复杂度 0 时黑屏录音降到 80MHz（后台「标准」档 5→0；同一段中文 0 和 5 识别逐字相同；积压 >2 秒自动回 160）
  - 4G 模组休眠默认打开（ML307C 出厂 sleepmode=0 从没睡过）：联网且对时后放高 DTR，每次联网请求前拉低
  - 拔线实测：录音 **80~93mA**（原 257）、暂停 **40~50mA**（原 193）、射频关 13~25
  - OTA：断点续传（Range 分段 1MB）、下载时界面定格（以前 SPI 失败让 LVGL 空转、进度卡 10%）、
    高速串口连续失败 2 次才退回 115200、升级后 10 分钟没联网自动回滚。**别把下载任务优先级降到界面(3)以下**
  - 串口实验命令：`at <指令>`、`msleep on|off`、`opus <复杂度>`、`cpu <MHz>`
- 实验结果有效的前提：SOC 一路下降、电压没钉在 4.19V。1.0.3 前心跳里的 charging 快充满时会误报「没在充」。
- 每块真实起点和时长记在会话目录的 `index.txt`，上传头用它，不再按「块号×块长」推算。
- 服务器可远程下发：`power_profile`（480 秒×4 段）、`power_profile_ab`（600 秒×2 段）、`shutdown`（真关机，1.0.2 起）。
  插入 `vm_device_commands` 即可，设备下次轮询执行。
